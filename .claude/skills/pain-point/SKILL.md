# 痛点の記録

このプロジェクトの目的は「複数のデモを作って苦しいところを体感し、そこから Mobile MR SDK を設計する」こと。痛点の記録はコードと同じくらい重要な成果物。

## 記録先

`docs/PAIN_POINTS.md` に追記する（新しいものを上に）。ファイルが無ければ見出しを付けて作成する。

## フォーマット

```markdown
## [YYYY-MM-DD] <Phase/デモ名>: <一言タイトル>

- **何が苦しかったか**: 具体的に。エラーメッセージや API 名を含める
- **どう対処したか**: 回避策・妥協した点。未解決なら「未解決」と書く
- **SDK ならどう解決するか（案）**: この痛みを将来のライブラリでどう吸収できそうか。思いつかなければ「未定」で良い
- **関連**: 該当コード（`demos/01-xxx/main.ts:42` 形式）や参考 URL
```

## 記録すべきものの例

- ブラウザ API の制約（iOS Safari の許可フロー、HTTPS 必須、イベントの発火順など）
- 毎デモで書かされる同じボイラープレート（← SDK 化の最有力候補）
- デバイス差・ブラウザ差で挙動が変わった箇所
- 座標系・回転・単位系で混乱した箇所
- デバッグが困難だった箇所（スマホ実機でしか再現しない等）

## 注意

- 「解決したから記録しなくていい」ではない。**解決できた痛みこそ SDK の機能候補**なので必ず残す
- 些細に見えても、2回目に遭遇したら必ず記録する（繰り返しは共通化のシグナル）
