# Mobile MR

スマートフォンとスマホ用VRゴーグルを使い、ブラウザだけで動くマルチプレイヤーMR（Mixed Reality）を試作するプロジェクトです。

複数人が同じ現実空間に集まり、各自のスマートフォンから同じ仮想オブジェクトを同じ場所に見られる状態を目指しています。まずデモを段階的に作って実装上の痛点を集め、最終的には共通部分を Mobile MR SDK として切り出す方針です。

> URLを開いた複数のスマートフォンを、同じ現実空間を共有するMRデバイス群に変える。

## 技術構成

- Vite + TypeScript
- Three.js / three-stdlib
- DeviceOrientation API / MediaDevices API
- js-aruco2（マーカー検出）
- MediaPipe Tasks Vision（手の追跡、全身の姿勢検出）
- WebSocket（Room内の姿勢共有）

ReactなどのUIフレームワークやWebXRを前提にせず、iPhoneのSafariを中心に検証しています。

## セットアップ

### 必要なもの

- Node.js 22.18以上
- npm
- PCでの確認: WebGLを利用できるモダンブラウザ
- 実機での確認: PCと同じLANに接続したスマートフォン

### 起動

```bash
git clone https://github.com/na2kera/mobile-mr.git
cd mobile-mr
npm ci
npm run dev
```

Viteが表示したURLをブラウザで開きます。

- PC: `https://localhost:5173/`
- スマートフォン: ターミナルの `Network` 欄に表示されたURL（例: `https://192.168.1.10:5173/`）

開発サーバーは、iOS Safariでカメラとセンサーを利用できるように自己署名証明書付きのHTTPSで起動し、LAN内へ公開されます。開発時の証明書警告は想定どおりの動作です。

### iPhoneで確認する

1. 開発用PCとiPhoneを同じWi-Fiへ接続します。
2. `npm run dev` の出力にある `Network` URLをiPhoneのSafariで開きます。
3. 初回は自己署名証明書の警告画面で詳細を表示し、サイトの閲覧を続けます。
4. 一覧からデモを選び、画面の「開始」をタップしてセンサー・カメラの利用を許可します。
5. スマートフォンを横向きにし、必要に応じてVRゴーグルへ装着します。

接続できない場合は、PC側のファイアウォール、両端末が同じLANにいること、ターミナルに表示されたIPアドレスを使っていることを確認してください。センサーやカメラの許可要求はユーザー操作が必要なため、URLを開いただけではデモは開始しません。

### Android（Chrome）で確認する

Android の Chrome は Fullscreen API が使えるので、全画面にするとアドレスバーが消え、画面が横向きに固定されます（06 以降のデモ）。iPhone と違いセンサーの許可ダイアログは出ません。

1. 開発用PCとAndroid端末を同じWi-Fiへ接続し、`npm run dev` の `Network` URLをChromeで開きます。
2. 自己署名証明書の警告では「詳細設定」→「（ホスト名）にアクセスする（安全ではありません）」で進みます。
3. デモの「開始」をタップし、カメラの許可ダイアログで「許可」を選びます。
4. **初回はアドレスバーが残ります。** 許可ダイアログの間にタップの効力が切れて全画面化が拒否されるためで、画面下に出る「タップで全画面表示」ボタンをもう一度タップすると全画面になり、横向きに固定されます（HUDに `fs=ok lock=ok` と出ます）。2回目以降はカメラの許可が記憶されているので「開始」だけで全画面になります。
5. 画面の上端からスワイプすると全画面が解除されアドレスバーが戻ります。「タップで全画面表示」ボタンが再び出るので、それをタップして戻ります。

うまくいかないときは、HUD（画面左下の小さな文字）を見てください。

- `sensor=granted no-events`（頭を動かしても視界が動かない）: Chromeの「⋮」→「設定」→「サイトの設定」→「モーションセンサー」が許可になっているか、またはアドレスバーの鍵アイコン→「権限」でこのサイトのモーションセンサーがブロックされていないかを確認します。
- `fs=` にエラー文が出る: 「タップで全画面表示」をもう一度タップします。Chromeの「PC版サイト」がオンだと表示が崩れるのでオフにします。
- `wake=ok` 以外（画面が途中で暗くなる）: 端末の省電力設定でChromeが制限されていないか確認します。
- iPhoneのChromeはFullscreen APIが使えないため（`fs=unsupported`）、アドレスバーは消せません。iPhoneではSafari（iOS 17.2以降）で開いてください。

## デモ別の追加準備

### マーカーを使うデモ（03 / 04 / 06 / 06-2 / 07 / 08 / 09）

1. 開発サーバーを起動します。
2. `https://localhost:5173/demos/03-marker-anchor/marker.html` を開き、マーカーを倍率100%で印刷します。
3. 印刷した黒い正方形の一辺が100mmであることを確認します。異なる大きさの場合は、デモURLへ実測値を `?markerMm=200` のように指定します。
4. 03ではマーカーをカメラに映し、04では同じマーカーを2台のスマートフォンから映します。

04で同じRoomに入る端末は、同じURLを開いてください。既定のRoom名は `demo` です。別のRoomを使う場合は、両端末に同じクエリ（例: `?room=my-room`）を指定します。中継用WebSocketサーバーはViteと同じプロセスで起動するため、別途サーバーを立ち上げる必要はありません。

### Hand Interaction（05）/ MR Volleyball（06）/ MR Darts（06-2）/ Surface Mapping（07）/ MR Splatoon（08）/ Person ID（09）

MediaPipeのWasmは依存パッケージから配信されます。検出モデルは未取得でも公式URLへフォールバックしますが、次のコマンドでローカルへ取得しておくと、実機から外部サイトへアクセスせずに試せます。

```bash
npm run fetch:models
```

モデルファイルは手が約7.8MB（`public/models/hand_landmarker.task`）、全身が約5.8MB（`public/models/pose_landmarker_lite.task`、09で使用）で、いずれもGit管理外です。

### MR Volleyball（06）

1. 03/04と同じマーカーを机に水平に置き、マーカーを挟んで向かい合います（1台だけなら相手側はbotが返球します）。
2. 両方の端末で同じURLを開いて開始し、まず机のマーカーを見ます。マーカーの真上に仮想のネットが立ち、立っている側（マーカーの下辺側=A、上辺側=B）が自動で決まります。同じ側に2人いると後から来た人は観戦扱いになるので、案内に従って反対側へ移動してください。
   - URLには05で求めた手の実寸較正 `?handScale=` を必ず付けてください（未指定は未較正の1。MediaPipeが申告する手の大きさは実際の半分程度なので、そのままでは手がボールの奥で空振りします）。較正値は05を開き、自分の手の長さ（手首のしわ→中指の先）[cm] ÷ HUDの `hand=` の値で求めます（例: 実測23cmで `hand=12cm` なら `?handScale=1.9`）。
3. ボールが自分の顔の前へ山なりに飛んでくるので、顔の前30〜60cmに手を出して触れると相手の顔の前へ自動で打ち返します（狙いは自動、手を速く振ると速い球）。落とした側の失点です。
4. ボールを見上げてマーカーが視界から外れても、ネットとボールはその場に残ります（ジャイロで回転だけ追従。歩くとずれるのでその場で遊んでください）。

ボールの物理・得点はViteに同居する対戦サーバー（`server/volleyball.ts`）が持ちます。同じroomに入る条件は04と同じ（既定 `demo`、`?room=` で分ける）で、ネットの高さ（`?netTop=`、既定は頭の高さから自動）もroom内で一致している必要があります。

### MR Darts（06-2）

1. マーカーを壁に天地を合わせて貼ります。マーカーの中心が仮想ダーツボードの中心（ブル）になります。ボードは標準サイズ（直径451mm）なので、検出距離を稼ぐためマーカーは拡大印刷（`?markerMm=` に実測値）を推奨します。
2. 参加する全員が同じURLを開き、開始画面で表示名を入力してから開始し、まず壁のマーカーを見ます（`?name=` での事前指定も可能。05で求めた `?handScale=` も付けてください）。参加した順に手番が回り、1人3投ずつ×3ラウンド（`?rounds=`）の合計点で競います。
3. 自分の番になると視界内に「あなたの番です」と出ます。ボードから1.5〜2.4mほど離れて立ち、顔の前に出した手を前へ速く振ると、手のひらの速さと左右の向きのままダーツが飛びます（左右の狙いの補正はありません。速度は振りのピーク、位置は減速を検出した時点のものを使います。上下だけは水平に振っても山なりで届くよう打ち出しに仰角 `?throwLoft=`、既定20°を足します。0で補正なし）。自分の番の間に振り始めた動作だけが投げになります。他の人はその場から見ていてください（他人のダーツも自分の端末で飛んで刺さります）。
4. 手番の人以外が投げても受け付けません。60秒投げないと0点で次の人へ移ります。

手番・採点・ダーツの着地はViteに同居するサーバー（`server/darts.ts`）が決めます。重力（`?gravity=`、既定9.8）とラウンド数はroom内で一致している必要があります。手の速度はトラッカーが過小に出やすいので、届かないときは `?throwGain=`（速さ）・`?throwLoft=`（仰角。上げるほど山なり）・`?gravity=` で調整してください（実機での較正値は未取得）。

### Surface Mapping（07）

1. マーカーを壁に天地を合わせて貼ります。マーカーを中心にした壁の範囲（既定 1.0m × 0.8m、`?surfaceW=` / `?surfaceH=`）が「Surface」（ID は `wall-<markerId>`）になり、その上の位置は UV（左上 0,0 〜 右下 1,1）で表します。
2. 参加する全員が同じURLを開き、開始画面で表示名を入力してから開始し、まず壁のマーカーを見ます（`?name=` での事前指定も可能。05で求めた `?handScale=` も付けてください）。Surfaceの枠と名札が出ます。
3. 人差し指だけ立てて壁を指すと、視線（目→指先）の先にカーソルが出て、指差しの間その場所に自分の色で描けます（半径 `?paintRadius=`、既定3cm）。描いた点は Surface ID + UV でサーバーに保存され、同じroomの全員に同じ場所で見えます（相手の頭とカーソルも表示）。右上の「全消去」（PCは `c` キー）でroom全員の絵を消します。
4. 手が取れないときは、画面を押している間だけ視界の中央に描けます（ゴーグル無しの手持ち確認用。`?gaze=1` で常時）。

ペイントの検証・順序・保持はViteに同居するサーバー（`server/surface.ts`。接続の共通部分は今回抽出した `server/room-server.ts`）が持ちます。マーカーとSurfaceの大きさはroom内で一致している必要があります。1 roomは8人まで（色は8色で、同時参加者は必ず別の色）、room総数は64まで、ペイントは1roomあたり4,000点まで保持し、超えると古い分から切り詰めて全員に配り直します（描き続けると1人で約4分半で到達。視界内に案内が出ます）。全員が切断してから10分でroomごと消えます（Wi-Fiの瞬断やSafariの画面切り替え程度では消えません）。全消去は2秒以内に2回押して確定です。

### ゴッドハンド（ex8-1）

1. マーカーを壁に天地を合わせて貼り、2mほど離れてマーカーを見ます。壁の手前の仮想シューターが、あなたの背後のゴール（白い枠）へシュートを撃ってきます。
2. ボールがオレンジに光ったら予告（0.9秒）。**パーに開いた手を素早く前へ突き出す**と、巨大な金色の手 = ゴッドハンドが約1.2秒実体化します（`?ghMinSpeed=` 既定2m/s、`?ghActiveSec=`）。その間にボールが触れればキャッチ、通されると失点（手が出ていたのに通されるとオーラが砕けます）。
3. シュートはだんだん速く・間隔が短くなります（`?ghSpeed=4`〜`?ghSpeedMax=9`）。5失点（`?lives=`）でリザルト→自動で次のゲーム。連続キャッチ数を競います。
4. 手が取れないときは画面タップ（PCはSpace）でも視界の先に発動します。通信は使いません（1人用）。

### MR Splatoon（08）

1. マーカーを壁に天地を合わせて貼ります。フィールドは床（既定 3.0m × 2.5m）を**四方の壁で囲んだ箱型のコート**です: 正面 = マーカーの壁（既定 3.0m × 2.4m）、左右と背面は現実に壁が無くても立つ仮想の壁（奥行きは既定 2.5m）。壁の下端は常に床に接続します。**塗れる空間の大きさ（幅・高さ・奥行き）と、床からマーカー中心までの高さ（実測。既定 1.2m）は俯瞰画面で開始前に変えられ**、サーバーが全員に配ります（URL では指定しません。変えると練習の塗りは消えます）。マーカーは壁の見やすい高さ（壁の高さ以下）に貼ってください。
2. 参加する全員が同じURLを開き、開始画面で表示名を入力してから開始し、まず壁のマーカーを見ます（`?name=` での事前指定も可能。05で求めた `?handScale=` も付けてください）。**個人戦**で、参加順に自分の色（8色。試合中は退出者の色を使い回しません）が割り当てられます。入室したら**練習**で、時間無制限に自由に塗れます（視界に「パーで塗る ／ グーで補充」の案内が出ます）。
3. **パーを開いている間、手からインクを連射**します（「目→手」の向き、約6発/秒）。インクタンクは満タンで50発。空になると撃てません。残量は**グーで補充している間だけ**、グーの手の横に浮かぶ筒の水位で見えます（パーで撃っている間は消えますが、空になると出て 1/4 ほど回復するまで出続けます。`?tankShow=always` で常に表示）。**撃つのをやめると回復し、グーにしている間は速く回復**します（撃った直後1秒は回復せず、グーなら約2秒、それ以外は約5秒で満タン）。壁か床に当たった場所が自分の色の飛沫（いびつな本体 + 進行方向に飛び散る滴。壁では下に垂れる）になり、他人の色は上書きされます（塗り替えた瞬間は白く光り、着弾の音が鳴ります。`?sound=0` で無音）。飛沫の形は全端末とサーバーで同じで、得点もその形で数えます。
4. 対戦はPCで [俯瞰画面](./demos/08-splatoon/overview.html)（`/demos/08-splatoon/overview.html`。カメラ・マーカー不要。スマホと同じ `?room=` で入る）を開き、必要なら「塗れる空間の大きさ」の幅・高さ・奥行きとマーカーの高さ（実測）を入れて「反映」（練習中か結果表示中だけ。カウントダウン中・対戦中は変えられません）、**「対戦開始」を押すと始まります**（カウントダウン `?waitSec=`、既定5秒 → 練習の塗りが消えて既定1分、`?matchSec=`）。**「対戦を終了」で途中でも結果に進めます**（カウントダウン中は「カウントダウンを中止」で練習に戻ります）。俯瞰画面にはコート全体・全員の頭と手・塗り・得点・インク残量がリアルタイムに出ます（ドラッグで回転）。対戦中はスマホの視界の上にも自分の順位と塗り率が大きく出ます。時間切れで塗った面積（壁 + 床のセル数）が最多の人の勝ち（壁の上のスコアボードに順位）。結果表示（8秒）のあと練習に戻り、次の対戦も俯瞰画面から始めます（結果表示中でも「次の対戦を開始」で始められます）。手が取れないときは、画面を押している間、視界の中央へ連射（PCは Space キー）。

着弾・塗りの格子・得点・試合の進行・フィールドの寸法（マーカーの高さを含む）はViteに同居するサーバー（`server/splatoon.ts`）が持ちます。重力（`?gravity=`、既定4）・試合時間（`?matchSec=`）・カウントダウン（`?waitSec=`）はroom内で一致している必要があります。1 roomはプレイヤー8人 + 俯瞰画面2台まで（役割別に数えます）。対戦開始を送れるのは俯瞰画面だけですが、役割はURL（`overview.html`）による自己申告なので、URLを知っていれば誰でも開始できます（LAN内のデモ用途。運営の端末で開く前提）。

### Person ID（09）

1. マーカーを壁に貼り、参加する全員が同じURLを開き、開始画面で表示名を入力してから開始し、まず壁のマーカーを見ます（共通座標系の原点。`?name=` での事前指定も可能）。参加順に色が割り当てられ、相手の頭の位置に半透明のアバターと名札が出ます（04と同じ仕組み）。
2. 相手の方を向くと、カメラに映った相手の体をMediaPipe Poseで検出して骨格を重ね、**検出した頭の位置とアバターの位置が「視線方向のずれ12°以内（`?matchAngle=`）かつ距離のずれ1.0m以内（`?matchDepth=`）」なら「この人 = その相手」**と判定して、骨格に相手の名前と色の名札を付けます。顔認識は使いません。対応が取れない人は「？」のままです。アバターの頭と検出した頭は線で結ばれ、ずれの大きさが見えます。
3. 判定した結果（誰をどこで見たか）はサーバー経由で相手に届き、相手の視界には「あなたから見えています（ずれ 0.2m）」と出ます。自分の体はゴーグル装着時に映らないので、確認は2台で互いを見合って行います。1台だけなら映った人は「？」のまま（検出の確認になります）。
4. 名札が付かないときはHUDの `tracks=`（角度・距離のずれ）を見て許容を広げるか、`?bodyScale=`（05の `handScale` と同じ実寸の較正。MediaPipeの申告が実際より小さければ1より大きく）で深度を合わせます。同時に検出する人数は `?poses=`（既定2）です。マーカーを見失っている間（位置はその場で凍結）も既定では対応づけを続け、画面に「相手はマーカーを見失い中」と出ます。`?strictTracking=1` でロスト中は対応づけも「見えています」の送信も止める厳密モードになります。

Player一覧と姿勢の中継はViteに同居するサーバー（`server/person.ts`）が持ちます。人物との対応づけは各端末が自分のカメラ座標系で行い、サーバーは判断しません。マーカーの設定はroom内で一致している必要があります。1 roomは8人まで。

## 現時点の主な制約

- スマートフォンのジャイロだけで追跡できるのは回転（3DoF）で、平行移動は取得できません。
- マーカーを使うデモでは、マーカーがカメラに映っている間だけ6DoF姿勢を更新できます。
- 背面カメラは単眼のため、現実映像そのものには左右眼の視差がありません。
- Shared RoomはLAN内での試作向けです。公開運用に必要な認証、永続化、レート制限は備えていません。
- iOS Safariではセンサー・カメラ・全画面表示に固有の制約があります。

既知の問題と試した対処は[docs/PAIN_POINTS.md](./docs/PAIN_POINTS.md)に記録しています。
