# 08-8. MR Splatoon（Pose カメラ）

`demos/08-splatoon/`（MR スプラトゥーン）と**同じ仕様**のスプラトゥーンを、「位置の取り方（自分のカメラの姿勢を field 座標系でどう決めるか）」だけ変えた比較用デモ。
背景と候補一覧は [docs/space-stability-options.md](../../docs/space-stability-options.md) §4 の **2b「アウトサイドイン（PC カメラ + MediaPipe Pose で人を追う）」**。
2a（[08-3 アウトサイドイン](../08-3-splatoon-outside-in/README.md)。PC の Web カメラでゴーグルのマーカーを追う）の**マーカーを外した版**で、08-3 を丸ごとコピーして差分を作った。08 のファイルは変更していない。08-3 のファイルはサーバー（`server/splatoon-outside-in.ts`）にオプションを足しただけ（オプション無しなら 08-3 の挙動のまま）。

**iPhone 実機は未確認**（PC のヘッドレス Chrome と Node のテストだけで確認）。

## 方式

```text
   [PC + Web カメラ]（部屋に固定。俯瞰画面 overview.html の「トラッカー」）
        │ MediaPipe PoseLandmarker で人物を検出 → 1 人ずつ 3D 化（肩幅の仮定で尺度）→ 頭の位置 + ヨー + 品質（部屋 = field 座標系）
        │ 誰がどのプレイヤーか: 入室順に「次の人は手を挙げてください」→ 手を挙げた人物に割り当て、以後は位置の近さで追跡
        ▼  track（id = 割り当てたプレイヤーの番号 trackId）
   サーバー（server/splatoon-pose-cam.ts = 08-3 のサーバーをオプション付きで別パスに登録）──tracked──▶ 各スマホ（位置はここから、回転はジャイロ）
```

- **スマホ**（`main.ts`）: 08-3 と同じ（位置はサーバーから、回転はジャイロ、アンカーは Y 回転 φ + 並進、原点の確定し直し・再接続・見失い明けでスナップ）。差分は次の 3 つと、案内の文言（「マーカー ID n を向けて」→「俯瞰画面の案内に合わせて手を挙げて」）・接続先のパス
  - **ヨーの緩やかな補正は既定で行わない**（`?yawSmooth=0`。スナップだけ）。トラッカーのヨーは体（耳・肩）の向きで、首だけ回して狙うとゴーグルの向きとずれる。08-3 のように品質の高い観測で緩やかに寄せると、首を回したまま狙っている間にコートが回ってしまう（Codex / Fable レビューの指摘）。ジャイロのドリフトが気になるときだけ `?yawSmooth=0.05` 等で有効にする
  - **いま追跡されていないと撃てない**（直近 `?shootTrackMs=`（1 秒）に自分の位置が届いていること）。08-3 はマーカーが一時的に隠れても最後の位置で撃てるが、08-8 で位置が届かないのは「割当が外れた・他の人と近づいて要確認」= 人物との対応が無効なので、古い位置で撃たせない。案内は「位置を見失いました。俯瞰画面の案内に合わせて手を挙げて割り当ててもらってください（撃てません）」
- **トラッカー**（`tracker.ts`。俯瞰画面の「トラッカー」の枠）:
  - 原点合わせは 08-3 と同じ（原点マーカー ID 0 か「追加マーカーの配置」のマーカー（床など）を同じカメラで見て「原点を確定」）。マーカーの検出は原点が未確定の間だけ走らせる
  - 人物: `src/shared/pose-tracker.ts`（09 と同じ PoseLandmarker。GPU → 失敗したら CPU で作り直す）→ `src/shared/pose-cam-track.ts` の `observePerson`:
    1. 両肩の 3D 距離（worldLandmarks）が `?shoulderM=`（既定 0.4m）になるように worldLandmarks 全体を拡大縮小し、09 と同じ最小二乗（`body-math.ts` の `solveBodyPlacement`）で画像に当てはめてカメラ座標系に置く → 原点合わせの「カメラ → field」で部屋座標系へ
    2. ヨー: 両肩と両耳のそれぞれ「左 − 右」から正面を出し（f = (L − R) × 上）、可視性で重み付けして足す。両耳が見えるときは耳（頭の向きに近い）を優先し、肩の重みを 0.25 倍に下げる
    3. 頭の中心: 両耳が見えれば、耳の中点・鼻・両目の中点それぞれから頭の中心を推定し（鼻は前 8cm・下 1cm、目は前 6cm・上 2cm を肩幅の仮定に比例させて引く）、可視性（`visibility`）で重み付けして平均する（ゴーグルで目が隠れると目の重みが下がる）。片耳しか見えなければ、見えている耳と鼻から出す（耳は頭の中心の真横なので正面方向の位置を、鼻は正面なので横方向の位置を受け持つ。高さは可視性の重み付き平均）。耳と鼻が揃わなければ肩の中点 + 上へ `?neckM=`（既定 0.25m）
    4. 送る位置 = 頭の中心 + 正面へ `?eyeFwdM=`（既定 0.1m。ゴーグルの前面のスマホのカメラ）
    5. 品質 = 肩の画面上の幅（`?poseQualityPx=` 60px で 1）× 正対の度合い × 肩の可視性。手を挙げている = どちらかの側で、手首が頭の中心より 15cm 以上高く、かつ同じ側の肘が肩より高い（頭をかく・髪を触る動作では割り当たらない）
  - 割当（`src/shared/pose-cam-assign.ts` の `PoseAssigner`）。見た目で人を区別しないので、取り違えるくらいなら割当を外して手を挙げ直してもらう（安全側。Codex / Fable レビューの指摘）:
    - 頭の位置が 0.3m 以内の検出は同じ人物の重複としてまとめる（可視性の合計が大きい方を残す）
    - 検出を「速度で予測した位置」に近い組から貪欲に対応づける。距離の上限は `?assignMatchM=`（66ms あたり 0.6m）を経過時間に比例させたもの。対応しない検出は新しい人物（未割当）
    - 割当済みの人物は **0.5 秒を超えて見失うと割当が外れる**（戻ってきても自動では戻らない。トラッカーの案内に「A を見失ったので割当を外しました。次の人（A）は手を挙げてください」）。`?assignLostMs=`（2 秒）見えなかった人物は一覧から消える（対応づけの前に消すので、古い人物が新しい検出に付かない）
    - 割当済みの 2 人が 0.5m 以内に近づく・1 つの検出に融合すると、両方を**要確認**にして位置を送らない（= 撃てない）。離れたときに、要確認になる前の位置と速度からの予測で「そのまま」の方が「入れ替え」より 0.3m 以上明確に近ければ続け、そうでなければ両方の割当を外す（案内「A が他の人と近づいて区別できなくなったので割当を外しました」）
    - 未割当の人物が `?raiseHoldMs=`（0.5 秒）手を挙げ続けたら、入室順でまだ割り当たっていない最初のプレイヤーを割り当てる（1 回に 1 人。直前の割当より前から挙げていた手は数えないので、同時に挙げた 2 人目は一度下ろして挙げ直す）
  - 実行時の例外（MediaPipe の推論）は try/catch し、検出のタイマーと描画ループは止めない
  - 推論が俯瞰画面の描画と競合しないように、推論の画像は長辺 640px（`?poseDetW=`、09 と同じ）、人数は 4 人まで（`?poses=`）。直近の推論時間が検出の間隔（`?trackIntervalMs=` 66ms）を超えたら、間隔を推論時間の 2 倍まで自動で延ばす（トラッカーの枠の `every=NNms`）
- **サーバー**（`server/splatoon-pose-cam.ts`）: メッセージ・検証（tracker 以外は track を送れない・値の範囲・レート 40 回/s・知らない番号は捨てる・有効なトラッカーは 1 台・未測定のプレイヤーの発射拒否）は 08-3 のサーバーと同じで足りるので、08-3 の `splatoonOutsideInServer` にオプションを足し、`{ path: "/api/splatoon-pose-cam", checkTrackIdCollision: false, dropMissing: true }` でもう 1 つ登録した（オプション無しの 08-3 は従来どおり。Node テストで両方を確認）。Room の状態は 08-3 とは別インスタンス（同じ room 名でも混ざらない）。ログの接頭辞は `[splatoon-pose-cam]`
  - `dropMissing: true`: 有効なトラッカーの track に含まれないプレイヤー（割当が外れた・要確認）は未測定に戻す（pose を配らず、発射は `not tracked yet` で拒否、tracked の配信からも外れる）。原点が未確定の track・有効なトラッカーの切断でも全員を未測定に戻す
  - `checkTrackIdCollision: false`: trackId はゴーグルのマーカーではないので、原点・追加マーカーの ID との衝突の検証（08-3 の番号の割り振りと配置の拒否）をしない
- **俯瞰画面**（`overview.ts`）: 08-3 のトラッカーの枠に「割当をやり直す」ボタン・案内「次の人（名前）は手を挙げてください」・人物一覧（`#n 名前（割当済み）/ 検出中（未割当）`、✋、頭の位置、品質、見失い）を足した。一覧の「位置合わせ」は「割当待ち（手を挙げる番）/ 人物 #n q= / 見失い」（トラッカーを動かしていない俯瞰画面では「追跡中 q=」）

## 2a（08-3）との違い

| | 2a（08-3 マーカー） | 2b（08-8 Pose） |
| --- | --- | --- |
| ゴーグルの準備 | 前面にマーカーを貼る（入室順の ID。再接続で貼り替えが要ることがある） | **不要** |
| 距離の精度 | マーカーの実寸（印刷で決まる）× 焦点距離 | **肩幅の仮定（`?shoulderM=`）に依存**。肩幅が 10% 違えば距離も 10% ずれる（Node テストで確認）。体格の違う人が混ざると人ごとにずれる |
| ヨー | マーカーの法線（ゴーグル = 頭の向き） | **耳（+ 肩）の向き = 体寄りの向き**。首だけ回すと頭の向きとずれるので、スマホは緩やかな補正をせずスナップだけ（`yawSmooth=0`） |
| 誰がどのプレイヤーか | マーカーの ID で自動 | **割当の儀式が要る**（入室順に手を挙げる）。0.5 秒を超えて見失う・他の人と近づいて区別できない・再接続・「割当をやり直す」で挙げ直し |
| 見失い明け | マーカーが見えれば自動で復帰。隠れている間も最後の位置で撃てる | 0.5 秒以内なら自動で復帰、それを超えると**手を挙げ直す**（別人に付かないように）。割当が外れている間は**撃てない** |
| PC の負荷 | js-aruco2（CPU）| PoseLandmarker（GPU / CPU）。原点確定後はマーカー検出を止める |
| サーバー | `server/splatoon-outside-in.ts` | 同じプラグインをオプション（`dropMissing` 等）付きで別パスに登録（`server/splatoon-pose-cam.ts`） |

## URL パラメータ

スマホ（`index.html`）は 08-3 と同じ（`fov` `camZoom` `markerMm` `fakecam` `fakehands` `room` `name` `autostart` `trackSmooth` `trackLostMs` `yawQuality` `yawSmooth`（08-8 は既定 0）`yawMaxRate` 等。08-8 だけ `shootTrackMs`（既定 1000。これより古い位置では撃てない）。08 の `gravityAlign` `detW` `fakeMarkers` 等は無い）。

俯瞰画面（`overview.html`）のうち 08-3 と同じもの: `room` `markerMm` `markerId` `gravity` `matchSec` `waitSec` `tracker=1` `camFov` `trackDetW`（原点マーカーの検出）`trackIntervalMs` `maxPoseError` `trackCamRes` `trackCam` `trackLockSamples` `fakecam` `fakeTrackCam`。
08-3 にあってこのデモに無いもの: `trackMarkerMm` `trackEyeBackM` `trackQualityPx` `fakePlayers`（印刷の `goggleMm` `players` も無い）。

このデモ固有（俯瞰画面）:

| パラメータ | 既定 | 意味 |
| --- | --- | --- |
| `shoulderM` | 0.4 | 肩幅の実寸の仮定 [m]（距離の尺度） |
| `neckM` | 0.25 | 首の長さの仮定 [m]（両耳が見えないときの頭の中心 = 肩の中点 + これ） |
| `eyeFwdM` | 0.1 | 頭の中心からスマホのカメラまで [m]（正面へ） |
| `poses` | 4 | 同時に検出する人数の上限（1〜4。増やすほど重い） |
| `poseDelegate` | auto | `gpu` / `cpu` / `auto`（GPU → 失敗したら CPU） |
| `poseDetW` | 640 | 推論に渡す画像の長辺の上限 [px]（09 と同じ。0 = video のまま（CPU のときは 640）） |
| `poseMinVis` | 0.5 | 点を使う可視性の下限 |
| `poseQualityPx` | 60 | 品質が 1 になる肩の画面上の幅 [px]（1280x720・`camFov=68` で約 6m 先の肩幅 0.4m） |
| `assignMatchM` | 0.6 | 同じ人物とみなす「速度で予測した位置」からの距離 [m]（66ms あたり。経過時間に比例） |
| `assignLostMs` | 2000 | これだけ見えなかった人物は一覧から消す [ms]（割当は 0.5 秒を超えて見失った時点で外れる） |
| `raiseHoldMs` | 500 | 手を挙げ続けてから割り当てるまで [ms] |
| `poseModel` | — | モデルの URL（既定は `public/models/pose_landmarker_lite.task` → 公式 URL） |
| `fakeBodies` | — | フェイクカメラの合成の体 `x,y,z,ヨー[deg];…`（頭の中心 [m]）。`window.__fakePose.bodies[i].raised = true` で手を挙げる、`window.__fakePose.hidden.add(i)` で隠す |
| `fakeGoggles` | 1 | 合成の体の目の可視性を下げる（ゴーグルで隠れる）。0 で目も見える |
| `fakePoseModel` | 0 | 1 でフェイクカメラの映像にも本物の PoseLandmarker を回す（読み込みと推論の経路の確認。観測は合成の体のまま） |

## PC で確認する手順

```sh
export PATH="$HOME/.nvm/versions/node/v22.23.2/bin:$PATH"
npm ci && npm run fetch:models
npm run test:pose-cam    # Node: pose-cam-track.ts / pose-cam-assign.ts の数学 + サーバー（Vite を PORT 5200 で起動して叩く）
npm run check:pose-cam   # ヘッドレス Chrome: スマホ 2 + 俯瞰 1 + トラッカー 1（+ 本物の推論の確認 1）。PORT 5199 / CDP_PORT 9343
```

`test:pose-cam` には、実装の生成関数を使わない**手計算の固定期待値**のテストを入れている（左肩が -X・右肩が +X → ヨー 0°、左肩 +Z・右肩 -Z → +90°、肩 0° と耳 90° は耳を優先（肩 0.25 倍）→ atan(4)、両耳の中点・鼻のオフセット・可視性の重み付き平均（z = 1.925）、片耳 + 鼻（正面・横向き）、片耳だけで鼻も無ければ肩 + 首、挙手（手首 15cm・肘が肩より上・頭をかく動作は除外）、肩幅の倍率 4/3、1280x720・FOV 90° の視線、向き合った人の左肩が画像の右に映る）。そのうえで合成の体との往復（傾いたカメラで 4 人・目は隠れる → 1mm / 0.01° 以内）、肩幅の仮定を 10% 変えると距離が 10% 変わること、割当（0.5 秒待つ・同時に挙げた 2 人目は流れ込まない・挙げ直し・歩いても追う・66ms で 0.6m を超える跳びは別人・上限は経過時間に比例・速度で予測・0.5 秒以内は復帰し超えたら外れる・期限切れの人物は対応づけの前に消す・やり直し・退室・Fable の S1 別人が同じ場所 / S2 すれ違い / S3 融合して分離で入れ替わらない・近づいて元の側へ離れたら続く・要確認中の見失いで両方外れる・S5 重複検出）、サーバー（別パスで別 Room・tracker 以外の track 拒否・未測定の発射拒否・番号での引き当てと存在しない番号の破棄・範囲外の破棄・pose の pos の上書き・dropMissing で track に居ないプレイヤーは撃てず 08-3 のパスは従来どおり撃てる・マーカー ID との衝突の検証は 08-3 だけ・2 台目のトラッカー拒否・バージョン不一致）を見る。

手で見るなら `npm run dev` のあと:

1. 俯瞰画面 `overview.html?room=x&tracker=1&fakecam=1&fakeBodies=-0.5,0,1.5,0;0.5,0,1.5,15` を開く
2. 「追加マーカーの配置」で床（ID 1、Z = 1.25）を使う → 反映 → トラッカーの枠に「原点マーカーが見えています」→「原点を確定」

## 既知の制約

- **距離は肩幅の仮定に依存**（体格の違いがそのまま距離の誤差。全員共通の 1 つの値）。MediaPipe の worldLandmarks 自体の尺度はモデルの推定で、肩の 3D 距離も腕の上げ下げ・前かがみで変わり得る
- **ヨーは耳・肩の向き**（首を回した頭の向きとは限らない）。そのためスマホは既定で緩やかな補正をせず、スナップ（初回・原点の確定し直し・見失い明け）だけ。スナップの間はジャイロのドリフトが残る
- **割当の儀式が要る**: 0.5 秒を超えて見失う（他の人に隠れる・カメラの視野外に出る）と割当が外れ、手を挙げ直すまでそのプレイヤーは撃てない（表示の位置は最後の値のまま）。再接続（瞬断・bfcache）でも id が変わるので挙げ直し。原点を解除して確定し直した場合も（0.5 秒を超えていれば）挙げ直し
- 人物の追跡は位置と速度の予測だけ（見た目の特徴は使わない）。割当済みの 2 人が 0.5m 以内に近づくと要確認になり、その間は 2 人とも撃てない（並んで立ち続けると撃てないまま）。離れた後に区別できなければ 2 人とも挙げ直し
- 2 人が**止まったまま**完全に重なり、その間に左右を入れ替えて離れると、要確認になる前の位置からの予測では入れ替わりを検出できず、入れ替わったまま続き得る（速度のあるすれ違い・重なりが 0.5 秒を超える場合は外れる）
- 背を向けた人は MediaPipe の左右が入れ替わることがあり、ヨーが反転し得る（正面の壁の方を向いて遊ぶ前提でカメラを壁側に置く）
- 原点合わせの誤差（PC の Web カメラには IMU が無く、1 枚のマーカーの傾きの誤差を救えない）は 08-3 と同じ
- 有効なトラッカーは 1 台（08-3 と同じ）。割当はトラッカーの画面のメモリにあるので、トラッカーのページを再読み込みすると全員挙げ直し
- PC の確認は合成の体（`fake-body.ts`。MediaPipe の出力の尺度・可視性のばらつき・検出の揺れは再現しない）。本物の PoseLandmarker は「読み込めて推論が回り、人の居ない映像で 0 人」までしか確かめていない
