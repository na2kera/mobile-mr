# 08-6. MR Splatoon（画面マーカー: モニタ / プロジェクタにマーカーを表示する）

`docs/space-stability-options.md` §4 の **候補 1d**（マーカーの物理を変える → ディスプレイ / プロジェクタに表示する）を、
08 スプラトゥーンと同じ仕様の別デモとして作ったもの。**位置の推定の数学は 08 のまま**で、変えたのは**マーカーの供給源**だけ。
紙に印刷する代わりに、俯瞰画面の PC に繋いだモニタかプロジェクタに、マーカー板（原点 ID 0 + 追加マーカー）を実寸指定で大きく出す。

- 紙より**大きく**（画面いっぱい。27 インチなら 1 枚 260mm、55 インチなら 540mm）
- 紙より**コントラストが高く**（自発光。プリンタの黒より黒い）
- **平面が保証される**（紙の反りや貼りズレが無い）
- **距離に応じて大きさを変えられる**（遠いときは 1 枚を大きく、近いときは複数枚を小さく）
- 追加マーカーの位置は画面上の px 差 ÷ (px/mm) から**自動で決まる**（巻き尺で測らない。貼りズレも無い）

**iPhone 実機は未確認**（PC のフェイクカメラとヘッドレス Chrome でのみ確認。下の「実機で確認すべき項目」）。

## 仕組み

```text
[PC] overview.html（俯瞰画面。役割 overview）          [PC のモニタ / プロジェクタ] markers-screen.html（役割 overview）
       │ 対戦開始 / 寸法 / 配置                                │ 画面の px 配置 → MarkerPlacement[]（face=wall、原点からの m）
       ▼                                                       ▼ 「room に反映」= 08 の markers メッセージ
    サーバー server/splatoon.ts（08 のまま。config.markers を welcome / markers で全員に配る）
       ▲
       │ pose / shot（08 のまま）
[iPhone] index.html（main.ts は 08 のコピー。画面に映ったマーカーを js-aruco2 で検出 → marker-anchor.ts で原点の姿勢）
```

- 画面 = 正面の壁（`wall` 面、Z = 0）。原点（room の `markerId`。既定 0）は**画面の中央**、追加マーカーはその周り（左右 → 上下 → 四隅の順、`RING_OFFSETS`）
- 画面の実寸はブラウザから取れない（CSS の `mm` は 96dpi 固定）ので、**対角のインチ**か **1mm あたりの px** を入力欄で指定して `localStorage` に保存する。`px/mm = hypot(screen.width, screen.height) / 対角 mm`
- 一辺（`markerMm`）とモードを変えると即座に描き直す。収まらない一辺はそのモード・枚数で収まる**最大に丸める**（HUD に `clamped=1`、パネルに警告）
- サーバーの上限は俯瞰画面 2 台（`MAX_OVERVIEWS`）なので、**俯瞰画面 + 画面マーカーで使い切る**（俯瞰画面を 2 枚開いていると画面マーカーが入れない）

## URL パラメータ

スマホ側（`index.html`）と俯瞰画面は **08 と同名・同義**（`fov` `camZoom` `markerMm` `fakecam` `fakehands` `fakeMarkers` `room` `name` `autostart` `gravityAlign` 等）。

画面マーカー（`markers-screen.html`）:

| パラメータ | 既定 | 意味 |
| --- | --- | --- |
| `room` | `demo` | スマホ・俯瞰画面と同じ room 名 |
| `markerId` | 0 | 原点の ID（room 設定） |
| `markerMm` | 150 | 黒い正方形の一辺 [mm]。**room 設定**（全員一致が必要。変えたら全員の URL に付けて入り直す） |
| `mode` | `multi` | `single`（遠い: 1 枚を大きく）/ `multi`（近い: 中央 + 周囲） |
| `count` | 4 | multi の追加マーカーの枚数（0〜8） |
| `ids` | 原点を飛ばして 1 から | 追加マーカーの ID（`1,2,3,4`） |
| `screenIn` / `screenMm` | 保存値 | 画面の対角の実寸（インチ / mm） |
| `pxPerMm` | 保存値 | 1mm あたりの px を直接指定（対角より優先。ヘッドレス確認はこれ） |
| `gap` | 0.2 | 隣り合うマーカーの間隔（一辺に対する比） |
| `invert` | 0 | `1` で白黒を反転（プロジェクタ実験用。下の注意） |
| `bg` | `black` | `white` で板の背景を白に |
| `panel` | 1 | `0` でパネルを隠して開く（`h` キーか左上のボタンで戻る） |
| `gravity` `matchSec` `waitSec` | 08 の既定 | room 設定（俯瞰画面と同じ値にする） |

## モニタで試す手順

1. 俯瞰画面の PC にモニタ（またはプロジェクタ）を繋ぎ、Chrome でそのモニタに `markers-screen.html?room=...` を開く（俯瞰画面の「画面マーカーを開く」リンク）
2. **画面の対角のインチ**を入れる（モニタの型番の数字。例: 27）。パネルに「1mm = 4.28 px（画面 597×336 mm）」のように出るので、定規で画面の幅を測って合っているか確かめる。
   合わなければ「1mm あたり px」を直接入れる。**Chrome のズームは 100%**（ズームすると CSS px の数が変わる）、macOS の「ディスプレイの解像度」は何でも良い（CSS px の総数と対角で換算する）
3. **一辺（mm）とモード**を決める。実用距離の目安は一辺の 10〜20 倍（150mm なら 1.5〜3m）。
   - 遠く（2〜3m）から遊ぶ: `single` で最大まで大きく
   - 近く（1〜1.5m）で遊ぶ: `multi`（4 枚）で小さく。近いと 1 枚ではカメラの視野から外れやすいので複数枚
   - 一辺を変えたら**全員のデモ URL と俯瞰画面に `?markerMm=` を付けて入り直す**（room 設定。この画面は自動で入り直し、違えば「設定と不一致」と出る）
4. **「全画面」**（Chrome の全画面。パネルは自動で隠れる。`h` で戻る）
5. **「room に反映」** → 全員の追加マーカーの配置がこの画面の配置になる（俯瞰画面の「追加マーカーの配置」の行にも入る。塗りは消えない）
6. 俯瞰画面で**マーカーの高さ（床から画面の中央まで）**を実測して入れる（08 と同じ `floorDrop`）
7. **輝度**: モニタの輝度は中〜高。暗いとカメラのノイズで黒枠の検出が落ち、明るすぎると白い余白がにじむ（bloom）ので、HUD の `marker=` が安定する値を探す。板の背景は既定で黒（画面全体が白だとカメラの自動露出が落ちる）
8. iPhone 側は 08 と同じ URL（`index.html`）。HUD の `marker=id=0+1+2+...` で複数枚が同時に使われ、`spread=` が小さければ配置が合っている

## プロジェクタの注意

- **台形補正（キーストーン）を切る**。補正が入るとマーカーが台形に歪み、平面の四角として推定した姿勢が実際とずれる（「平面が保証される」利点が消える）。レンズシフトか、投影面に正対させて置く
- 投影面は**平らな白い壁 / スクリーン**。凹凸や布のたるみはそのまま姿勢誤差になる
- プロジェクタの「黒」は投影面の色（照明が当たると灰色）。**部屋を暗く**して黒枠のコントラストを確保する
- `?invert=1` の反転は、**js-aruco2 の検出器が「黒い枠 + 白い余白」を前提**（`AR.Detector.getMarker` は枠のセルが黒でないと候補を捨てる）なので、**今の検出器では反転したマーカーは検出されない**。「明るい所を黒にしたい」プロジェクタ実験用に残しているだけで、遊ぶときは反転しない
- スマホのカメラの露出はプロジェクタの光で暴れやすい。HUD の `marker=` が `lost` を繰り返すなら投影を暗くする

## 実機で確認すべき項目（未確認）

- **画面のモアレ・リフレッシュレート**: カメラの露出時間とモニタのリフレッシュ（60 / 120Hz）の干渉で縞やちらつきが出て、黒枠の検出が落ちないか。落ちるなら iPhone の露出を下げる（明るい部屋）か、モニタのリフレッシュレートを変える
- **反射**: 光沢のあるモニタに照明が映り込むと余白が飛ぶ。マット面か、照明の位置を変える
- **紙より遠くまで検出できるか**: 同じ一辺の紙（`markers.html`）と画面で、HUD の `marker=` が出る最大距離と `err=` / `Δ=` を比べる。画面の方が遠くまで・安定して取れれば候補 1d の効果
- **斜めからの安定**: 08 の症状（斜め 45〜60° で箱型コートが傾く・飛ぶ）が、画面の大きなマーカーで軽くなるか。`spread=` と立方体の角のぶれで比べる（docs/space-stability-options.md §5 の指標）
- **距離に応じた切り替え**: 遠い（`single` 最大）と近い（`multi`）で、それぞれ検出率と `spread=` がどうか。一辺を変えると全員の入り直しが要る運用が実際に許容できるか
- **プロジェクタ**: 台形補正を切った状態で検出できるか。部屋の明るさと黒枠のコントラスト
- **輝度と自動露出**: 画面が視野の大半を占めると iPhone の露出が落ちて周りが暗くなる（パススルーとして見づらい）か
- 08 の実機未確認項目（俯瞰画面の対戦開始・寸法・マルチマーカー・重力での水平化）はそのまま

## 既知の制約

- **一辺（`markerMm`）は room の接続設定**なので、画面で変えるたびに全員が URL を変えて入り直す必要がある（08 のプロトコルを変えない前提。`docs/PAIN_POINTS.md` に記録）
- マーカーは全部同じ大きさ（08 の `markerSizeM` が 1 つなので、「中央だけ大きく周りは小さく」はできない）
- 画面 = 正面の壁だけ。床・左右・背面の追加マーカーは紙（`markers.html`）と俯瞰画面の入力欄で従来どおり（画面の配置を反映すると入力欄の他の行は消えるので、紙のマーカーを併用するなら反映後に俯瞰画面で足す）
- 俯瞰画面の上限 2 台を画面マーカーが 1 台ぶん使う
- 画面の実寸は利用者の入力頼み（ブラウザから取れない）。入力ミスは「原点から 5m 超」でしか弾けない
- 反転（`?invert=1`）は今の検出器では検出されない（上の「プロジェクタの注意」）
