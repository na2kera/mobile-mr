# ex9-1 化身（番外編）

イナズマイレブンの「化身」の 3D モデルを、**ボタン 1 つで自分の背後に出す** MR デモです。iPhone（iOS Safari）+ スマホ用 VR ゴーグル（StereoEffect の左右 2 眼）、複数人で同じ room に入ります。
09-person-id を後で土台にするので 9 番台の ex にしています。

全 4 段階のうち、いまは **段階 1**（1 台で、ボタン → 主観のオーラ + 上を向くと見える化身 + PC の俯瞰画面での表示）です。
**PC（Node テスト + ヘッドレス Chrome）で確認済み・実機未確認**。

| 段階 | 内容 | 状態 |

## 使い方

1. 08 の[マーカー印刷ページ](../08-splatoon/markers.html)（既定 150mm、ID 0）を印刷して壁に貼る。
2. スマホで `https://<Mac のホスト名>.local:5173/demos/ex9-1-keshin/` を開き、名前を入れて開始（センサー・カメラ許可 → 全画面）。まず壁のマーカーを見る。
3. PC の Chrome で `https://localhost:5173/demos/ex9-1-keshin/overview.html` を開く（同じ room。既定 `demo`）。
4. スマホの画面下の **「化身」ボタン**（ゴーグルから一度外して押す。PC では `K` キーでも可）→ サーバーが確定した時点で全員の画面で演出が始まる。
   - 0〜0.4s: 足元〜腰の高さに光の粒とオーラの柱が吹き上がる
   - 0.3〜1.1s: 化身が下から約 1m せり上がりながら不透明度 0 → 既定値（腰のクリッピング平面は動かないので「腰から生えてくる」）
   - 1.0〜1.5s: 決めポーズ。その後もオーラはゆっくり揺らめき続ける
   - もう一度押すと逆再生で約 1.0s で消える。連打は受け付ける（途中で反転したら、いまの見え方の続きから）
5. スマホを正面に向けている間は化身を描かず、視界の周りにオーラだけが揺らめく。**見上げる（40° 以上）と、前に傾いた自分の化身**が見える。

## 仕組み

- 自己位置は 08 と同じ（js-aruco2 + ジャイロ。壁のマーカー 1 枚・重力で水平化 `worldUp`）。共有する座標はマーカー座標系（X 右・Y 上・Z 壁から部屋側。Y が鉛直上であることは `scripts/test-keshin.mjs` で固定）。
- 体の向き（body yaw）: `f = h(−Z_cam) + s·h(−Y_cam)`（h は水平面への射影、s は見上げ +1 / 見下ろし −1）を正規化。送信側だけで指数平滑（`?yawSmoothSec=0.25`）し、受信側は受け取った向きをそのまま使う（`keshin-math.ts` の `bodyForward` / `smoothYaw`）。
- 化身の配置（`keshin-math.ts` の `keshinModelMatrix`）: 足元（原点）= 頭 − `eyeH`、体の向きの後ろへ `back`。`back` は読み込んだ上半身の +Z 側の端（召喚前後の姿勢の大きい方）× 拡大率 + 0.25m（「上半身の前面が頭の中心から少なくとも 0.25m 後ろ」）。
- 演出は `src/shared/keshin-timeline.ts` の純粋関数 `keshinTimeline(t, mode)`（ステージの経過時間だけで決まる。隠れた状態なし）。途中反転はサーバーがステージの開始時刻を「いまの見え方と同じになる時刻」にずらして全員に配る。途中入室者は welcome のスナップショット（`changedAt` と `now`）から演出なしで同じ見え方になる。
  スナップショットの pose には、サーバーが受け取ってからの経過 `poseAgeMs` が付き、受信側は受信時刻をその分だけ過去にずらす（`keshin-math.ts` の `poseReceivedLocal` / `effectiveTrack`。古い pose を今届いた marker と誤解しない）。
- 再接続（プロトコル v2）: タブごと・役割ごとのランダムな session 鍵（`sessionStorage` の `keshin-session-player` / `keshin-session-overview`）を WS の URL に付ける。
  同じ役割・同じ鍵で入ってきたら、サーバーは古い接続に「別のタブ・端末に置き換えました」を送って閉じ、化身の番号・on・changedAt・色・直近の pose を引き継ぎ、古い id の leave を全員に配る
  （画面ロックや Wi-Fi の瞬断で半分切れた接続が残っている間に、同じ人が 2 体にならない）。置き換えられた側のタブは再接続をやめ、画面に「このタブは止まっています」と出す（タブを複製して同じ鍵になっても奪い合わない）。
  役割が違えば同じ鍵でも別人（置き換え・満員の免除・引き継ぎは同じ役割のときだけ）。きれいに切れた後の再入室（再読み込み）も 60 秒以内なら引き継ぎ、その間その人の色と番号は予約扱い（他の人に渡さない）。空になった Room も 60 秒残す。本人の画面は出ていたら演出なしで出たまま。
- 主観: 腰の切断面を支点に前傾（自分の画面でだけ）。前傾の角度と前後は**モデルごとの既定値**（`keshin-assets.ts` の `KESHIN_SPECS[].self`。下の「主観の見え方の既定値」）で、`?selfLean=` / `?selfFaceAhead=` / `?selfBack=` で全モデル共通に上書きできる。
  見上げ角が `lookUpDeg` 以上で完全に見え、`lookUpDeg − 10` 以下では描かない。不透明度 `?selfOpacity=0.55`、目から `?nearFade=0.6` m 以内は消す（頭の中心のワールド位置からの距離なので左右の目で同じ）。
  消す帯（0.6〜0.75m）は、深度の前描画と色を**同じ画素で捨てる**ディザで境目をぼかす（アルファで薄くすると、その帯だけ深度の前描画が無くなって内側の面が透けるため）。
- 半透明はモデルの README の makeGhost（深度だけ書く複製を先に描く）で内側が透けない。発光部分（目・宝石・炎の外炎）は濃く残す。ランスロットの頭の炎（元は不透明）も体と同じ扱い（深度の前描画 + 体の不透明度）。
- シェーダーは化身を作った直後とモデルを差し替えた直後に先にコンパイルする（初めて見上げた瞬間・初めて出た瞬間に固まらないように）。
  描画ループの本描画の直前に、化身（と視界の周りのオーラ）を一時的に表示して**キャンバスへ実際の設定のまま 1 回描く**（直後の本描画が autoClear で消すので見えない）。
  1×1 のレンダーターゲットへ描くと出力の色空間が Linear になって別のプログラムになり、`renderer.compile` はクリッピングの状態を設定しないので平面の数が違うプログラムになるため（どちらも見上げたときに作り直しが走っていた）。
  時間とリンクしたプログラムの数は HUD の `warmup=`（例 `model 32ms programs=4→8`）と実機ログの `event=warmup` に出る。`check:keshin` が「初めて見上げたとき・化身が初めて出たときに新しくリンクされるプログラムが 0 本」を確かめる。
  読み込み直後の上半身の測定（全頂点 × 2 姿勢を CPU でスキン変形）の時間も `measure=` に出る（PC で 14 / 23 / 16ms。30ms を超えないので事前計算の JSON は作っていない）。
- オーラは加算合成の粒子で、位置は頂点シェーダーが時刻から計算する（CPU 負荷は粒子数に依らない）。視界の周りのオーラはカメラの子で 0.6〜1.2m 先の実際の 3D 位置に置く（ポストエフェクトは StereoEffect と相性が悪いので使わない）。
  視線から 25° 以内は空け、外側ほど濃く、小さな火の粉が下から上へ立ち上って消える。片目の視野の縁に大きく柔らかい低アルファのもやを置く。
- マーカーの枠は `track` が `marker` のときだけ描く（見失っている間は最後のアンカーのままなので、ずれた位置に出て紛らわしい）。
- PC のフェイクカメラの映像の左上に出る黄色い横長の帯は、共通のフェイクカメラ（`passthrough-camera.ts` の `drawCheckerboard`）の「映像が更新されている」ことを示す動くバー。実機には出ない。
- pose には「信用できるか」を付ける: `track`（`marker` = 直近 `?trackOkMs=500` 以内にマーカーを見た / `gyro` = アンカーはあるがマーカーを見ていない / `none` = まだアンカー無し）と `ageMs`。
  俯瞰画面は `gyro` で `ageMs` が伸びるにつれ化身を薄く（`?staleMs=3000` で半分、以降その薄さで位置を止める）、`none` は化身を出さず「位置未確定」だけ。主観の化身はジャイロのワールドで描くのでマーカーが無くても出る。

### 主観の見え方の既定値（確定。self-sweep.png を見て方針側が決めた）

| 化身 | 前傾 | 顔の前への距離 | 理由 |
| --- | --- | --- | --- |
| 魔神 | 50° | 1.0m | 35° / 0.25m では兜の裏と細い腕しか見えなかった。前へ大きく出して倒すと、見上げ 45〜60° で顔（開いた口）と広げた腕の輪郭が入り、目の近くで消える頂点は 2% |
| ペガサス | 35° | 0.7m | 35° / 0.25m は髪の房の裏が重なり、頂点の 43% が目の近くで消えていた。0.7m 前へ出すと翼・髪・肩が入り、消える頂点 12% |
| ランスロット | 35° | 0.7m | 見上げ 45° で兜・角・肩当て・胸当てが入り、消える頂点 14%。35° / 0.25m（兜・肩当て・胸が読める）は頂点の 45% が消えている |

どの設定でも化身は本人と同じ向きなので、顔を前から見ることはない（前へ出すほど背中側、上に置くほどあご側から見る）。

## 実機の確認手順（PC の確認は実機で効く証明にならない）

準備: `npm run fetch:keshin` → `npm run dev`。iPhone で上の URL を開き、ゴーグルに入れる。PC で俯瞰画面を開く。

| 1 | ログが出る | `grep keshin-phone logs/client.log \| tail` | 1 秒ごとに `state: fps=...` の行、入室で `event=welcome`・モデルで `event=model-loaded`（読み込み時間 ms） |

| 4 | マーカー検出の重さ | `det=` | ≤ 30ms（08 と同程度） |
| 5 | 演出 | ボタンを押して俯瞰画面とスマホで見る | 押してから 0.5s 以内に全員で始まる。柱 → せり上がり → 決めポーズが約 1.5s。もう一度押すと約 1.0s で消える。連打しても見え方が飛ばない |

| 7b | 固まらない | 初めて見上げた瞬間 | カクつかない（HUD の `warmup=` が出ていること。ログの `event=warmup` の時間を記録） |

| 9 | 俯瞰画面の位置と向き | スマホを持って壁から 1〜2m に立ち、体ごと向きを変える | 化身が本人の背後（壁と反対側）にせり上がり、本人と同じ向きを向く。見上げ・見下ろしでも化身の向きが変わらない |
| 10 | 信用度 | マーカーから目を離す（横・上を向く） | 名前の横が `marker` → `gyro n.ns` になり、化身が薄くなる（3 秒で半分）。マーカーを見直すと `marker` に戻る |
| 11 | 途中入室 | 化身を出したまま、俯瞰画面をリロード | 演出なしで出切った化身が出る |
| 12 | 床の高さ | 俯瞰画面の床の目安（輪）と実際の床 | 輪が床から ±20cm 以内（ずれたら `?eyeH=` を実測値に） |

## 既知の制約・未確認

- **実機未確認**（上の手順すべて）。
- 主観の前傾 35° では、見上げると化身の顔を下（あご側）から見る形になる（化身の顔は前下を向くため）。見え方は実機で `?selfLean=` / `?selfFaceAhead=` / `?selfBack=` を振って決める。
- 主観の化身は 3DoF（ジャイロ）なので、歩いても化身は頭についてくる（位置はマーカーのアンカーに依らない）。
- スキンメッシュの境界球は使わず、カリングを切っている（README どおり）。見えていないときは描かない（見上げフェード 0・不透明度 0 で非表示）。
- ペガサスのオーラの帯（`PA_FX_Aura`）は主観では出さない（自分の頭を囲んで視界を横切るため）。俯瞰画面では翼を開き切ったあとに出す。
