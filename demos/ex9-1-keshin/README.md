# ex9-1 化身（番外編）

イナズマイレブンの「化身」の 3D モデルを、**ボタン 1 つで自分の背後に出す** MR デモです。iPhone（iOS Safari）+ スマホ用 VR ゴーグル（StereoEffect の左右 2 眼）、複数人で同じ room に入ります。
09-person-id を後で土台にするので 9 番台の ex にしています。

全 4 段階のうち、いまは **段階 3**（カメラで見た人で相手の化身の位置を決める = ハイブリッド。あわせて人の形のマスクの修正と「背中からビヨーンと出る」見え方）です。

## 使い方

1. 08 の[マーカー印刷ページ](../08-splatoon/markers.html)（既定 150mm、ID 0）を印刷して壁に貼る。
2. スマホで `https://<Mac のホスト名>.local:5173/demos/ex9-1-keshin/` を開き、名前を入れて開始（センサー・カメラ許可 → 全画面）。まず壁のマーカーを見る。
   - iPhone で Safari の Fullscreen API がオフ（`requestFullscreen` が無い）だと、起動時にオンにする手順（設定 → アプリ → Safari → 詳細 → 機能フラグ → Fullscreen API）の案内が出る。Web から設定アプリは開けないので手順を見せるだけ。「このまま続ける」で閉じれば、アドレスバーが残る全画面風のまま遊べる（issue #91。PC 確認済み・**実機未確認**）。
3. PC の Chrome で `https://localhost:5173/demos/ex9-1-keshin/overview.html` を開く（同じ room。既定 `demo`）。
4. スマホの画面下の **「化身」ボタン**（ゴーグルから一度外して押す。PC では `K` キーでも可）→ サーバーが確定した時点で全員の画面で演出が始まる。
   - 0〜0.4s: 足元〜腰の高さに光の粒とオーラの柱が吹き上がる
   - 0.3〜1.1s: 化身が下から約 1m せり上がりながら不透明度 0 → 既定値（腰のクリッピング平面は動かないので「腰から生えてくる」）
   - 1.0〜1.5s: 決めポーズ。その後もオーラはゆっくり揺らめき続ける
   - もう一度押すと逆再生で約 1.0s で消える。連打は受け付ける（途中で反転したら、いまの見え方の続きから）
5. スマホを正面に向けている間は化身を描かず、視界の周りにオーラだけが揺らめく。**見上げる（40° 以上）と、前に傾いた自分の化身**が見える。

## 仕組み

- 自己位置は 08 と同じ（js-aruco2 + ジャイロ。壁のマーカー 1 枚・重力で水平化 `worldUp`）。共有する座標はマーカー座標系（X 右・Y 上・Z 壁から部屋側。Y が鉛直上であることは `scripts/test-keshin.mjs` で固定）。
- 体の向き（body yaw）: `f = h(−Z_cam) + s·h(−Y_cam)`（h は水平面への射影、s は見上げ +1 / 見下ろし −1）を正規化。送信側だけで指数平滑（`?yawSmoothSec=0.25`）し、受信側は受け取った向きをそのまま使う（`keshin-math.ts` の `bodyForward` / `smoothYaw`）。
- 化身の配置（`keshin-math.ts` の `keshinModelMatrix`）: 足元（原点）= 頭 − `eyeH`、体の向きの後ろへ `back`。`back` は読み込んだ上半身の +Z 側の端（召喚前後の姿勢の大きい方）× 拡大率 + 0.25m（「上半身の前面が頭の中心から少なくとも 0.25m 後ろ」）。
- 演出は `src/shared/keshin-timeline.ts` の純粋関数 `keshinTimeline(t, mode)`（ステージの経過時間だけで決まる。隠れた状態なし）。途中反転はサーバーがステージの開始時刻を「いまの見え方と同じになる時刻」にずらして全員に配る。途中入室者は welcome のスナップショット（`changedAt` と `now`）から演出なしで同じ見え方になる。
  スナップショットの pose には、サーバーが受け取ってからの経過 `poseAgeMs` が付き、受信側は受信時刻をその分だけ過去にずらす（`keshin-math.ts` の `poseReceivedLocal` / `effectiveTrack`。古い pose を今届いた marker と誤解しない）。
- 再接続（プロトコル v2）: タブごと・役割ごとのランダムな session 鍵（`sessionStorage` の `keshin-session-player` / `keshin-session-overview`）を WS の URL に付ける。
  同じ役割・同じ鍵で入ってきたら、サーバーは古い接続に「別のタブ・端末に置き換えました」を送って閉じ、化身の番号・on・changedAt・色・直近の pose を引き継ぎ、古い id の leave を全員に配る
  （画面ロックや Wi-Fi の瞬断で半分切れた接続が残っている間に、同じ人が 2 体にならない）。置き換えられた側のタブは再接続をやめ、画面に「このタブは止まっています」と出す（タブを複製して同じ鍵になっても奪い合わない）。
  役割が違えば同じ鍵でも別人（置き換え・満員の免除・引き継ぎは同じ役割のときだけ）。きれいに切れた後の再入室（再読み込み）も 60 秒以内なら引き継ぎ、その間その人の色と番号は予約扱い（他の人に渡さない）。空になった Room も 60 秒残す。本人の画面は出ていたら演出なしで出たまま。
- 主観: 腰の切断面を支点に前傾（自分の画面でだけ）。前傾の角度と前後は**モデルごとの既定値**（`keshin-assets.ts` の `KESHIN_SPECS[].self`。下の「主観の見え方の既定値」）で、`?selfLean=` / `?selfFaceAhead=` / `?selfBack=` で全モデル共通に上書きできる。
  見上げ角が `lookUpDeg` 以上で完全に見え、`lookUpDeg − 10` 以下では描かない。不透明度 `?selfOpacity=0.55`、目から `?nearFade=0.6` m 以内は消す（頭の中心のワールド位置からの距離なので左右の目で同じ）。
  消す帯（0.6〜0.75m）は、深度の前描画と色を**同じ画素で捨てる**ディザで境目をぼかす（アルファで薄くすると、その帯だけ深度の前描画が無くなって内側の面が透けるため）。
- 半透明はモデルの README の makeGhost（深度だけ書く複製を先に描く）で内側が透けない。発光部分（目・宝石・炎の外炎）は濃く残す。ランスロットの頭の炎（元は不透明）も体と同じ扱い（深度の前描画 + 体の不透明度）。
- シェーダーは化身を作った直後とモデルを差し替えた直後に先にコンパイルする（初めて見上げた瞬間・初めて出た瞬間に固まらないように）。
  描画ループの本描画の直前に、化身（と視界の周りのオーラ）を一時的に表示して**キャンバスへ実際の設定のまま 1 回描く**（直後の本描画が autoClear で消すので見えない）。
  1×1 のレンダーターゲットへ描くと出力の色空間が Linear になって別のプログラムになり、`renderer.compile` はクリッピングの状態を設定しないので平面の数が違うプログラムになるため（どちらも見上げたときに作り直しが走っていた）。
  時間とリンクしたプログラムの数は HUD の `warmup=`（例 `model 32ms programs=4→8`）と実機ログの `event=warmup` に出る。`check:keshin` が「初めて見上げたとき・化身が初めて出たときに新しくリンクされるプログラムが 0 本」を確かめる。
  読み込み直後の上半身の測定（全頂点 × 2 姿勢を CPU でスキン変形）の時間も `measure=` に出る（PC で 14 / 23 / 16ms。30ms を超えないので事前計算の JSON は作っていない）。
- オーラは加算合成の粒子で、位置は頂点シェーダーが時刻から計算する（CPU 負荷は粒子数に依らない）。視界の周りのオーラはカメラの子で 0.6〜1.2m 先の実際の 3D 位置に置く（ポストエフェクトは StereoEffect と相性が悪いので使わない）。
  視線から 25° 以内は空け、外側ほど濃く、小さな火の粉が下から上へ立ち上って消える。片目の視野の縁に大きく柔らかい低アルファのもやを置く。
- マーカーの枠は `track` が `marker` のときだけ描く（見失っている間は最後のアンカーのままなので、ずれた位置に出て紛らわしい）。
- PC のフェイクカメラの映像の左上に出る黄色い横長の帯は、共通のフェイクカメラ（`passthrough-camera.ts` の `drawCheckerboard`）の「映像が更新されている」ことを示す動くバー。実機には出ない。
- pose には「信用できるか」を付ける: `track`（`marker` = 直近 `?trackOkMs=500` 以内にマーカーを見た / `gyro` = アンカーはあるがマーカーを見ていない / `none` = まだアンカー無し）と `ageMs`。
  俯瞰画面は `gyro` で `ageMs` が伸びるにつれ化身を薄く（`?staleMs=3000` で半分、以降その薄さで位置を止める）、`none` は化身を出さず「位置未確定」だけ。主観の化身はジャイロのワールドで描くのでマーカーが無くても出る。

## 段階 2: 相手の化身と、人の形で隠す処理

- **相手の化身をスマホに描く**（`remote-keshins.ts`）: 俯瞰画面と同じ `keshin-view.ts` の「他人用」。相手の申告した頭の位置と体の向き（マーカー座標系）を、自分のアンカーで自分のワールドに直し、その背後・同じ向きに置く（`keshin-math.ts` の `markerToWorld` / `markerFwdToWorldYaw`）。
  見上げ角に関係なく描く。不透明度 `?otherOpacity=0.85`。演出は全員同じ timeline。自分のアンカーが無い（`track=none`）間は描かず、視界内に「壁のマーカーを見てください（相手の化身の位置が分かりません）」。
- **信用できるか**: 俯瞰画面と同じ `effectiveTrack` / `poseReceivedLocal`（`remoteDisplay`）。`marker` は通常、`gyro` は経過が伸びるほど薄く（`?staleMs=3000` で半分、以降その薄さで位置を止める）、`none`・通信切れ（`?peerLostMs=5000` 届かない）は描かない。
  **長く見失った相手は消す**: `gyro` の経過が `?staleHideMs=8000` を超えたら 0.8 秒のフェードで消し（HUD の理由 `stale-hiding` → `stale`、ログ `event=remote-hidden ... reason=stale`）、マーカーを見直した pose が届けばまた出す（`event=remote-shown ... after=stale`）。
  経過だけで決まる純粋関数（`remoteDisplay`）で状態を持たない。俯瞰画面は今までどおり（半分の薄さのまま）。
- **跳びをなめらかに**: 表示中の頭の位置と向き（自分のワールド）を最新の目標へ時定数 `?remoteSmoothSec=0.25` で寄せる（`smoothToward`。持つ状態は表示中の値だけ）。
  自分のアンカーの跳び（マーカーを見直したとき。段階 1 の実機で最大 1.6m）でも目標が動くので同じ仕組みでなめらかになる。`?snapM=3` 以上離れたら即座に移す。跳びの大きさ（目標と表示の差の直前 1 秒の最大）を HUD とログの `jump=` に出す。
- **人の形で隠す**（`keshin-occlusion.ts`）: カメラに人が写っている画素のうち、**持ち主（相手）の頭よりカメラから遠い部分**の相手の化身（とその足元・腰のオーラ）を描かない。自分の化身・視界の周りのオーラは隠さない。
  - 前後の判定: 断片のカメラからの距離が「持ち主の頭（表示中の、なめらかにした位置）までの距離 − `?maskDepthMargin=0.15`（m）」より遠いときだけ捨てる。距離は眼ごとのカメラ位置で出す（深度の前描画も同じ条件）。
    相手が**こちらを向いている**と化身は相手の向こう側なので、相手の体の輪郭の分だけ隠れる（相手の体が化身より手前）。相手が**向こうを向いている**と化身は自分と相手の間（人より手前）に来るので、人の形の上でも隠さない。
  - 人の形は MediaPipe PoseLandmarker の segmentation mask（`src/shared/pose-tracker.ts` の `outputSegmentationMasks`。既定 false で 09 は変わらない。モデルは `public/models/pose_landmarker_lite.task`、無ければ公式 URL）。
    `numPoses` は最初から `?maskPoses=3`（使っている最中に作り直さない。GL コンテキストが 2 組になる山を避ける）。推論に渡す画像の長辺 `?maskDetW=512`（マスクもこの大きさ。320 では iPad で一度も人が出なかったので上げた。09 は 640）。
    推論はコールバック版の `detectForVideo` で、マスクはコールバックの中でだけ読む（`getAsFloat32Array`。MediaPipe の GL コンテキストは three と別なので CPU で読み戻す）。複数人は画素ごとの最大で 1 枚の R8 テクスチャにまとめる。
    確信度は `?maskEdge=0.3,0.7` の smoothstep で裾を切ってから 0..255 にする（確信度をそのままディザの確率にすると、人の周りに点状の穴が散るため）。
    **前提: マスクの行 0 は画像の上**（d.ts には書かれていない。MediaPipe の `MPImage.getAsImageData` が同じ `readPixels` で上下を反転せずに ImageData にしていることからの推定。逆なら人の形が上下反転して見えるので、実機で最初に確かめる）。
  - 隠し方: 相手の化身のマテリアル（色と深度の前描画の両方）とオーラの粒の fragment で、`gl_FragCoord` から「その眼のビューポート内の位置」を出し（眼のビューポートは `onBeforeRender` で `renderer.getCurrentViewport` から）、
    **背景の VideoTexture と同じ UV 変換**（`passthrough-camera.ts` の `coverUvTransform` = `texture.matrix`。cover・`camZoom`）でマスクの座標に直し、人で、かつ持ち主の頭より奥なら discard。
    縁は `?maskDilatePx=3`（マスクの px、周り 8 方向の最大）だけ膨らませ、境界は段階 1 の目の近くと同じディザでぼかす。純粋な式は `keshin-math.ts` の `maskUvFromFragment`（Node テスト済み）。
  - **マスクは Pose の検出の時点のもの**なので、相手が速く動くと隠れる範囲が少し遅れる（最大で 1/`maskHz` 秒 + 推論の時間。仕様）。
  - 重さ: Pose の読み込み（モデル・wasm・GPU の初期化）は、隠す処理が有効で相手が 1 人でも入室したら先に済ませる（時間は `event=mask-ready ... load=..ms`）。
    回すのは相手の化身（モデルかオーラ。出現の最初と消える終わりのオーラだけの時間も含む）が視野に入っていそうな間だけで、回数は `?maskHz=15` が上限、マーカー検出をしたフレームでは回さない。
    **遅い端末では回数を自動で下げる**（`MaskHzGovernor`。`?maskHzAuto=0` で止める）: 検出を回している間の fps を 1 秒ごとに数え、直近 2 秒の平均が 30 未満なら 1 段下げ（15 → 10 → 6 → 4）、5 秒続けて 45 を超えたら 1 段戻す。
    `?maskHz=` は上限（8 なら 8 → 6 → 4）。持つ状態は「今の段」だけで、段を変えたら fps の記録を捨てて新しい 2 秒 / 5 秒を見てから次を決める（純粋関数 `decideMaskHzLevel`、Node テスト済み）。変えたらログ `event=mask-hz 15→10 reason=fps2s=19<30`。
    `?occlude=0` で丸ごと止める（Pose も読み込まない）。Pose の読み込み・推論に失敗したら隠さずに描く（HUD とログに理由）。
  - **GPU で人が出ないとき CPU に切り替える**（`?delegate=auto` のときだけ）: GPU で 0 人のまま `?maskProbeAfterMs=10000` 続いたら、CPU の PoseLandmarker を（モデルを使い回して）作り、同じフレームで 3 回比べる。
    CPU だけ人が出たら CPU に切り替える（`event=mask-delegate GPU→CPU reason=gpu-0-people cpu=2/3 gpu=0/3`）。両方 0 人なら人が写っていないだけかもしれないので GPU のまま、30 秒後にまた比べる（4 回まで。`event=mask-delegate-probe keep=GPU reason=both-0 ...`）。GPU で一度でも人が出たら比べない。
    手で比べるなら `?delegate=cpu` / `?delegate=gpu`。
  - HUD / ログ（1 秒ごとの `state:` 行にも同じものが入る）:
    `occlude=ready(GPU numPoses=3) run=1 on=1 pose=18ms mask=21ms hz=14 maskHz=15/15 age=40ms person=1 poses=1 masks=1 in=512x288 lum=97 dg=GPU found=120/130`
    - `pose=` 推論 1 回、`mask=` マスクの更新 1 回の全体（推論 + 読み戻し + 変換。テクスチャのアップロード自体は次の描画）、`hz=` マスクの更新回数 / 秒、`maskHz=今の段/上限`、`age=` マスクの古さ
    - **人の形が出ないときの切り分け用**: `poses=` 1 回の結果の人数（`landmarks.length`）、`masks=` マスクの枚数（`segmentationMasks.length`）、`in=` Pose に渡した入力の大きさ、
      `lum=` 入力の平均の明るさ（0〜255。0 に近ければ video → canvas の drawImage が黒い）、`dg=` 実際の delegate、`found=人が出た回数/回した回数`、`probe=` GPU と CPU の比べ方の状態
    - 相手ごとに `remote 名前(id) #番号 track 経過 dist=距離 drawn=描いているか(理由) fade=薄さ jump=跳び`
    - 出来事は `remote-first-draw` / `remote-hidden`（理由）/ `remote-shown` / `remote-snap` / `mask-start` / `mask-stop` / `mask-ready` / `mask-failed` / `mask-hz` / `mask-delegate` / `mask-delegate-probe` / `camera`
  - **`?maskDebug=1`**: 相手がいなくても・化身が視野に無くても Pose を読み込んで回し、画面の右上に「Pose に渡した入力の縮小画像（`in=` と `lum=`）」と「最新のマスク（白 = 人。`poses=` `masks=` delegate）」を小さく出す。
    実機で人の形が出るかを 1 台で目で見て確かめる用（隠す処理そのものは相手の化身が視野にあるときだけなのは同じ）。
- PC 確認用のフェイク（`?fakeperson=1`）: 相手の申告位置に `fake-body.ts` の合成の体を立たせ、フェイクカメラの映像に描いて、同じ形をマスクにも使う（MediaPipe の代わり。マスク → テクスチャ → シェーダーの経路を確かめる）。

    濃さは毎フレーム「いま − 最後にその人を見た時刻」で決める（`mirrorVisibility`）。カメラの停止・Pose の失敗で結果が来なくなっても、保持 → フェード → 消える（最後の位置に残り続けない）。
    結果が `?poseStallMs=1000` 来なければ HUD に `pose=STALLED`、ログに `event=pose-stalled`（戻ったら `pose-resumed`）、画面の下に「人の検出が止まっています」。
  - 足元・腰のオーラにも同じ濃さを掛ける（他人用の化身すべて。スマホの相手の化身・俯瞰画面の信用度の薄さもオーラに掛かる。自分用の見上げフェードは足元のオーラに掛けない）。
- **誰の化身か**（簡易な対応。制約）: 化身を出している（出ている・消える途中の）プレイヤーを参加順に並べる。**誰にも付いていない化身**は、空いている人を近い順（深度の小さい順）に割り当てる。1 人なら一番近い人に付く。
  **一度付けた人は画像の上の頭の位置（正規化座標。両目の中点）で追いかけ、見えている間はほかの人へ付け替えない**（`mirror-math.ts` の `assignMirrorTracked`）。
  - 同じ人とみなす画像の上の距離は、最後に見えてからの時間で広げる（`mirrorImgGate`: 0.05 から 0.5/秒で広がり、上限 `?mirrorMatchImg=0.15`）。Pose がその人を 1〜2 回取りこぼしても、隣に並んだ人（3m で肩を並べると画像の上で 0.12〜0.2）へ移らない。
  - 3D の頭の距離は補助（コストに 1m あたり 0.05 を足すだけ）。Pose の距離の推定は体の大きさの仮定で数十 cm ぶれるので、3D の距離で対応づけると外れる（2026-09-28 の実機で、同じくらいの距離の 2 人の間を 0.1 秒おきに行き来した。下の「既知の制約」）。
  - 付けた人を見失っても、`?mirrorHoldMs=500` の間はほかの人へ付け替えない（`hold`。戻れば同じ化身）。保持を過ぎてから、残った人へ近い順で付ける（`new`）。
    保持の間に同じ人とみなす範囲は、広げた範囲と「前回の位置から、ほかの人までの一番近い距離 × 0.5」の小さい方（ほかの人 = 今回の結果のほかの人と、前回見えたときの隣の人）。
    元の人が消えて隣の人（画像の上で 0.12）だけが残っても、範囲が 0.15 まで広がって隣の人を `tracked` にすることはない（Codex のレビューで再現した不具合。以前は 300ms で付け替わっていた）。隣の人がいなかった人は、今までどおり広げた範囲で追いかける。
  - 持つ状態は化身ごとの「前回の人（画像の上の位置と 3D の頭、そのときの隣の人までの画像の上の距離 `nearImg`）と最後に見えた時刻」だけ。**1 人の人には化身を 1 体だけ**付ける（組の数が最大 → コストの合計が最小の全探索。ゴーグル側と `assignMaxMin` を共有）。
  2 人から 1 人に減っても、残った人の化身は付け替わらない（消えた人の化身はその位置で保持 → フェード）。前の人を別の化身に取られた化身は、保持せずにすぐフェードに入る（`event=reassign-fade`）。
  **顔や服で見分けてはいない**ので、2 人が画像の上で重なるほど近づく・すれ違うと入れ替わりうる。化身が 1 人も出ていないときは画面の下に「ゴーグルの人が化身ボタンを押すと出ます」、出ているのに人が写っていないときは「カメラに人が写っていません」。
- **化身の見せ方**: スマホの「他人用」と同じ部品（`keshin-view.ts`）・置き方（頭の背後・同じ向き = カメラの方を向く）・出現の演出・不透明度（`?otherOpacity=`）・足元と腰のオーラ。
  人の形で隠す処理（持ち主の頭より奥だけ）も同じ仕組みで、持ち主の頭は Pose で出した頭。
  `?keshinH=` も効く。**iPad から 2m くらいだと 3m の化身の頭が画面から切れやすい**ので、少し離れて立つ（3m 以上）か `?keshinH=2` のように下げる。
- **重さ**: 段階 2 の検出回数の自動調整（fps が 30 を切ると 15 → 10 → 6 → 4）をそのまま使う。化身の描画は毎フレームの補間でなめらかにし、Pose の回数は自動調整に任せる（鏡は 20〜30fps でも見られる）。
- **HUD / ログ**（tag `keshin-mirror`、1 秒ごとの `state:` 行）: `fps` `render`、`cam=`（ラベル・`facing=`・`fov=`）、`occlude=`（段階 2 と同じ: Pose の ms・mask の ms・人数 `poses=`・`masks=`・`in=`・`lum=`・`dg=`・`maskHz=`）、
  `persons=`（人ごとの深度・向き・向きの出どころ・床・画像の上の頭 `img`）、`keshin=`（プレイヤー → 何番目の人（付け方 `tracked` / `new` / `hold` / `displaced` / `none` と、判断に使った値 `dImg=`（前回の人から付けた人までの画像の上の距離）`dImg2=`（2 番目に近い人まで）`gate=`（その結果のしきい値）`d3=`（3D の距離））・描いているか（理由）・濃さ）。
  `event=assign` は付け方が変わったときだけ出る（結果の中の人の番号の入れ替わりでは出さない）。例: `p28→1(tracked dImg=0.004 dImg2=0.160 gate=0.050 d3=0.21)`。
  出来事は `camera` / `person-found` / `person-lost` / `assign` / `keshin-on` / `keshin-off` / `keshin-shown` / `keshin-hidden` / `model-loaded` / `error` ほか段階 2 と同じ `mask-*`。
- **PC 確認用**: `?fakecam=1&fakeperson=1` でフェイクカメラの映像に合成の人（`fake-body.ts`。本人の左手首に赤い印）を描き、Pose の代わりに同じ人の骨格と人の形のマスクを使う。
  立つ位置は `?fakePeople=x,y,z,yawDeg`（カメラ座標系の頭と体の向き。0 = カメラの方。`;` で複数人。既定 `0,0.25,-3.2,0`）。

## 段階 3: カメラで見た人で相手の化身の位置を決める（ハイブリッド）

ユーザーの要望: 「壁（マーカー）を見てしばらく経っても、iPhone のカメラで人の位置を把握して、お互いを見たときにいい感じに化身が出るようにしたい」。

### A. 人の形のマスクを実機で効かせる

- 実機（iPad の Chrome・Mac の Safari・ゴーグルの iPhone）で `poses=1 masks=1 ... person=0`（Pose は人を見つけ、マスクも返すのに中身が空）だった。
  `vision_bundle` の `MPMask.getAsFloat32Array` は GPU のマスクを `readPixels(FLOAT)` で読む（iOS / iPadOS は `RGBA`、それ以外は `RED`）。この読み戻しが効かない環境では 0 のまま返ると見ている（**原因は未確定**）。
  `setFromFloat` 自体は、値が 0..1 でも 0..255 でも人になる（Node テストで確認。NaN だけは人にならない）ので、実機の person=0 の原因ではない。
- **診断**（HUD とログの 1 行）: `mmax=`（マスクの最大）`mmean=`（平均）`mfrac=`（0.5 を超える割合）、NaN があれば `mnan=`、0..255 で来ていれば `x255`（自動で 1/255 を掛ける）。
- **骨格から描く人の形**（`keshin-occlusion.ts` の `skeletonPersonShape`）: Pose の 33 点（正規化座標）から、頭 = 円（両耳の中点、半径は両耳の間隔 × 0.55 か肩幅 × 0.3）、胴 = 両肩・両腰の四角形（腰が見えなければ肩から肩幅 × 1.3 下まで）、
  首・腕・脚 = 太さが肩幅に比例するカプセル（首 0.45・腕 0.32 / 0.28・脚 0.42 / 0.36）を塗ってマスクにする（フェイクの人と同じ `setFromImageData` の経路）。
- **出どころの切り替え**（`?maskSource=seg|skel|auto`、既定 auto。HUD とログの `msrc=`、切り替えは `event=mask-source`）: 持つ状態は「今の source」1 つだけ。
  auto は、人を見つけている（poses > 0）のにマスクの最大（0..1 に直した値）が `?maskMinMax=0.1` 未満の結果が **5 回続いたら** skel、seg に値が出る結果が 5 回続いたら seg に戻す
  （途中で反対の結果が出たら数え直し。0.1 付近でばたつかない。人のいない結果では変えない）。状態は「今の source と、反対の結果が続いた回数」だけ。鏡モードとゴーグル側の両方に効く。

### B. ハイブリッド（ゴーグルのスマホ。`?posMode=hybrid`、既定）

| 項目 | 使うもの |
| --- | --- |
| 方向（画面のどこに相手がいるか） | 自分のカメラで検出した相手の体（Pose → 09 の `body-math.ts` で 3D 化 → ジャイロの回転 + カメラの位置で自分のワールドへ。**マーカーに依らない**） |
| 距離 | 申告と自分のアンカーが新しければ 申告までの距離 × `?distW=0.7` + カメラの推定 × 0.3、古ければカメラの推定だけ |
| 誰か | 候補は ① 新しい申告の方向と検出の方向が `?matchDeg=15` 以内（declared-dir）② 前回結んだ人と頭が `?matchM=0.5` m 以内（tracked）。**1 回の全探索で「結ぶ組の数が最大 → コストの合計が最小」**（段ごと・近い組からの貪欲だと、成り立つ組を失う）。どちらも無ければ、相手 1 人・検出 1 人のときだけ結ぶ（only-one。**体の向きが合うときだけ**。新しい申告がある相手はさらに方向の差が `?onlyOneMaxDeg=45` 以内のときだけ）。**自分のアンカーがまだ無い**（申告の向きを自分のワールドに直せない）ときに限り、化身を出している相手が 1 人・検出 1 人なら向きを確かめずに結ぶ（only-one-unchecked。別の人に付くことがある）。**古い申告の方向だけでは結ばない**（別人に付け得る）。新しく結ぶときは下の「別の人に付けない関門」を通す。結び方と結ばなかった理由はログの `event=remote-match` |
| 相手が見えていない間 | **最新の**申告位置 + 見えていた間に学んだ補正（マーカー座標系の「見えた頭 − 申告位置」。見えなくなった瞬間に飛ばないよう直近 `?corrRecentSec=0.5` 秒の外れ値を除いた平均。観測は直近 `?corrWindowSec=3` 秒だけ持つ）× 弱まり（最後に見えてから `?corrDecaySec=10` 秒で 0 へ） |

- 純粋な数学は `keshin-hybrid.ts`（`detectionToWorld` / `matchRemotes`（`matchRemotesDiag`）/ `facingDiffDeg` / `blendDistance` / `hybridHead` / `robustMeanV3` / `correctionAt`。Node テスト済み）。補正の隠れた状態は窓の観測だけ（教訓 4）。
- **別の人に付けない関門**（2026-09-28 の実機で、化身を出していない人が 1 人だけ映ると、申告が古いときは only-one でその人に付き、その差を補正として学んでいた）:
  - **体の向き**（`?facingMaxDeg=60`）: 相手の申告の体の向き（相手のジャイロから出したマーカー座標系の `fwd`。位置が古くても向きは正しい）を自分のアンカーで自分のワールドに直し、検出した人の肩の線から出した体の向き（`mirrorBodyFacing`）と比べる。
    差が 60° を超える人には、only-one でも declared-dir でも初めての tracked でも結ばない（理由 `facing`）。60° は自分のアンカーの向きの誤差（単一マーカーで十数度）・肩の線のぶれ・申告の遅れを見込んだ値。
    ゴーグルで顔が隠れて鼻で前後を決められない人（鼻が肩の中点より 3cm 以上前に出ていない）は、線の向きだけで比べる（±180° を区別しない。差は 0〜90°）。
    相手の向きが無い（相手の申告が `none` など）ときは only-one で結ばない（理由 `no-facing`）。
    **自分のアンカーがまだ無い**ときだけは、化身を出している相手が 1 人・検出した人も 1 人なら向きを確かめずに結ぶ（`match=only-one-unchecked`。HUD とログに出る）。
    アンカーが無いと申告の向きを自分のワールドに直せず、以前は相手 1 人・検出 1 人でも化身が出なかった（Codex のレビュー）。アンカーができた後は、上の向きの関門に戻る。
  - **補正**（`?corrGateM=1.5`）: 補正を学べている相手（最後に見えてから `?corrDecaySec=` 以内）は、「最新の申告位置 + 学んだ補正（弱める前）」から 1.5m を超えて離れた人に結ばない（理由 `corr-gate`）。
    **直近の頭の位置での再捕捉**（tracked: その相手に前回結んだ頭の位置（自分のワールド。最後に見えてから 3 秒以内）から `?matchM=0.5` 以内）には補正の関門を掛けず、体の向きだけ確かめる。
    自分や相手のアンカーが跳んで予測位置がずれたあとに見失っても、本人が同じ所に戻ればすぐ結ぶ（以前は予測が 2.2m ずれると `corr-gate` で断り、補正が弱まり切るまで最大約 10 秒続いた。Codex のレビュー）。
    前回結んだ頭の位置は、今ある「最後にカメラで見えた頭」（`lastCamHead`）を使い、新しい状態は足していない。
  - **自分のアンカーが大きく変わったら補正を捨てる**（`?corrResetM=0.3`）: 補正はマーカー座標系で持っているので、自分のアンカーが変わると古い補正は別の所を指す。
    マーカーを見直した補正量 `Δ`（HUD の `marker=... Δ=`）が 0.3m を超えたフレームで、全員の補正の窓を捨てる（ログ `event=corr-reset Δ=...m remotes=N`）。見えている相手はすぐ学び直す。
  - 関門は**続けて追いかけている tracked**（前回の Pose の結果でも結んでいた人）には掛けない（振り向く途中や、相手のアンカーが跳んで申告が動いた瞬間に、見えている本人を手放さない）。
    持つ状態は増やしていない（「前回の結果でも結んでいたか」は最後に見えた時刻と前回の結果の時刻が同じかで決める）。
- **申告の方向による対応づけ（declared-dir）は実機では効きにくい**: 2026-09-28 の実機で、申告の方向とカメラの方向のずれ（`dAng=`）は 29°〜167°（単一マーカーの自己位置の誤差と申告の古さ）で、`match=declared-dir` は 2 回だけだった。
  既定の `?matchDeg=15` は上げていない（29° 以上のずれを拾うほど広げると角度で人を見分けられなくなり、2 人並ぶと取り違える。別の人に付けない役目は体の向きと補正の関門が持つ）。2 人とも壁のマーカーを見た直後など、アンカーが正確なときだけ効く。
- Pose は相手が 1 人でも入室していれば回す（化身が出ていなくても、割り当てと補正の学習のため。回数は段階 2 の自動調整）。人の形で隠す処理を止めても（`?occlude=0`）Pose は回す（`?posMode=declared` なら回さない）。
- 向き: 申告された体の向き（相手のジャイロ）を自分のアンカーで直したもの。自分のアンカーが無ければ肩の線から（鏡の `mirrorBodyFacing`。ゴーグルで顔が隠れるので、鼻は前後の補助だけ）。
- 見えている相手は、自分のアンカーが無くても・相手の申告が `none` や古くても描く。
- 見えていない相手の薄さは **max(申告側, 最後に見えてから側)**。消すのは両方とも描けないときだけ（申告が新しい相手は、補正が 0 になっても消えない。申告が古い相手は、最後に見えてから `?staleHideMs=8000` + 0.8 秒で消える）。
  補正の基準（学習と適用）は最新の申告位置（段階 2 の「stale で位置を止めた値」とは別。それは declared モードの表示だけに使う）。この判定と補正の弱まりは同じ時刻（最後に見えた時刻）から数える。純粋関数 `planRemote`（`RemoteKeshins.plan` の中身）を Node テストで時刻を進めて確かめている。
- 画面の端で見え隠れしても、補正（見えていた位置 = 申告 + 補正）と表示のなめらかさ（`?remoteSmoothSec=`）で化身は飛ばない。
- 人の形で隠す処理の持ち主の頭はハイブリッドの頭。
- **比べる**: `?posMode=declared`（段階 2 と同じ）/ `camera`（見えている間はカメラだけ。最新の結果で見えなくなったら 0.2 秒で消す）/ `hybrid`。
  HUD とログの相手ごとの行に `src=`（camera / hybrid / declared+corr / declared / hidden）`camD=`（カメラの推定距離）`decD=`（申告距離）`corr=`（補正の大きさ × 弱まり）`n=`（窓の件数）`dAng=`（申告の方向とカメラの方向の角度）`match=`（結び方: `declared-dir` / `tracked` / `only-one` / `only-one-unchecked`）
  `why=`（結ばなかった理由: `facing` / `corr-gate` / `no-facing` / `dir` / `no-candidate`、結んでいれば `-`）`fDeg=`（検出ごとの、申告の体の向きとの差 [deg]。`,` 区切り）`corrM=`（検出ごとの、申告 + 補正からの距離 [m]）。
  ログの `event=remote-match` にも、結ばなかった理由（例 `p3:-(facing)`）と検出ごとの `fDeg=` `corrM=` が出る。次の実機テストで `?facingMaxDeg=` / `?corrGateM=` を決める材料にする。
- **サーバーは変えていない**（各端末の描画だけ。共有の状態の補正はしない）。今後の課題: pose に「誰をどこで見たか」（09 の `seen`）を載せて俯瞰画面にその点を出す（プロトコルを上げる）。

### C. 「背中からビヨーンと出る」見え方（他人用すべて: 鏡・ゴーグルの相手・俯瞰画面。自分用は今のまま）

- 化身の腰（溶けた下端）を本人の頭より `?waistAboveHeadM=0.3` 上に置き、背中からの距離も後ろへ（上半身の前面 + `?backClearM=0.4`。`?keshinBack=` を指定すればそちら）。本人の頭・肩に化身の体が被らない。
- 腰で平らに切らず、腰から上 `?dissolveM=0.6` m を下へ行くほど透明にする（画素ごとのディザ + 横方向にゆっくり揺らめくノイズ。深度の前描画も同じ条件で捨てる。ランスロットのマント・ペガサスの帯も同じ）。
- 本人の背中（頭の 0.35m 下・少し後ろ）から化身の腰へ、上へ・後ろへ曲がりながら太くなる光の流れ（`keshin-stream.ts`。3 次ベジェの管を頂点シェーダーで曲げる。加算合成・流れるノイズ・沿って上る粒）。
  太さ `?streamR0=0.07` / `?streamR1=0.32`、明るさ `?streamK=0.7`、粒 `?streamN=90`。色は化身ごとのオーラの色。出現では流れが先に伸び（0〜0.45 秒）、その先で化身がせり上がる。人の形で隠す処理も効く。
  管の断面の横向きは「本人の後ろ向き × 上」で固定（曲線はこの 2 つの面の中にあるので、どこでも曲線に直交してねじれない）。
- 足元の柱（今のオーラ）は `?footAuraK=0.3` に控え、床から背中の高さまで。腰の渦は溶けた腰のまわり。
- `?look=0` で段階 2 までの見え方（比べる用）。値は起動時のログ（`event=start ... look waistAbove=...`）に出る。
- **既定値は候補**（`node scripts/sweep-keshin-look.mjs` → `logs/keshin-check/look-sweep.png`。鏡モード・iPad 前面 106° のまね・人 1.3m / 2.5m・4 体 × 4 設定）。確定は方針側が画像を見て行う。
  既定は方針側が look-sweep を見て決めた値（腰 頭 +0.3・間隔 0.4・流れの明るさ 0.7。シートの L1 に近い）。

### Mac の Chrome で実カメラの Pose を確かめる（ヘッドレスではなく手で）

ヘッドレスはフェイクカメラ（人がいない）なので、本物の Pose が人を見つけるかは確かめられない。Mac の内蔵カメラで自分を写して確かめる手順:

1. `npm run dev` のあと、Mac の Chrome で `https://localhost:5173/demos/ex9-1-keshin/?maskDebug=1&name=Mac`（ポートは dev サーバーの表示に合わせる。`fakecam` は付けない）
2. 名前を入れて開始し、カメラを許可する。HUD の `cam=` に選んだカメラと `facing=` `why=` が出る（Mac は超広角が無いので `why=environment(no-ultra-wide)`）
3. カメラから 1.5〜2.5m 離れて、**腰から上（できれば膝まで）**が写るように立つ。右上の縮小画像の上段が入力、下段がマスク
4. 見ること: 下段に自分の形が白く出る・`poses=1 masks=1`・`found=` の左が増える・`lum=` が 30 以上。`dg=` と `pose=..ms` を記録
5. 顔だけが大きく写る距離（0.5m 以内）まで近づくと `poses=0` になるかも記録する（iPad の前面カメラで一度も人が出なかった原因の候補）
6. `?delegate=cpu` と `?delegate=gpu` で開き直して、`poses=` と `pose=..ms` の差を記録する
7. ログは `grep keshin-phone logs/client.log | grep -o 'occlude=.*' | tail`

手で見るなら `npm run dev` のあと、`/demos/ex9-1-keshin/?camZoom=1&fakecam=1&autostart=1&name=PC` と `overview.html` を並べて、`K` キーで出し入れ・マウスで見上げる。

**人の形が出ないとき**（`person=0` のまま。ログの `occlude=` の行で切り分ける）:
`lum=` が 0〜10 → 入力が真っ黒（video → canvas の drawImage の問題）。`poses=0 masks=0` で `lum=` が普通 → Pose が人を見つけていない: 近すぎないか（顔だけ・上半身の一部だけだと見つからない。全身か腰から上を入れる）、
`dg=GPU` なら `probe=` が `switched-cpu` になったか（なっていなければ `?delegate=cpu` で比べる）、`in=` が小さすぎないか（`?maskDetW=640`）。`poses=1 masks=0` → マスクだけが返っていない（MediaPipe 側）。`poses=1 masks=1 person=0` → マスクの確信度が低い（`?maskEdge=0.1,0.5`）。

**fps が 30 を切るときの下げ方**（検出の回数は自動で 15 → 10 → 6 → 4 まで下がる。`maskHz=今/上限` とログの `event=mask-hz` を見る）（`mask=` を見て、効く順）: `mask=` × `hz=` が 1 秒あたり 300ms を超えていれば `?maskHz=8`（検出の回数を半分に）→ `mask=` が大きければ `?maskDetW=256`（推論とマスクを小さく）→ `?maskPoses=1`（相手が 1 人なら）→
`?delegate=cpu` / `gpu`（ログの `mask-ready` に出た実行先と逆を試す）→ 最後に `?occlude=0`。`mask=` が小さいのに fps が低いなら、隠す処理ではなく描画（`tris=` `calls=`）の重さなので `?auraN=` や `?otherOpacity=` 側で比べる。
どれで何 fps になったかを README に記録する。

## 既知の制約・未確認

- 段階 1 は実機確認済み（2026-09-27）。**段階 2 は実機未確認**（上の S1〜S8）。**鏡モードも実機未確認**（上の M0〜M6）。**段階 3 も実機未確認**（上の H1〜H6）。
- 段階 3 の B は、カメラの推定距離が体の大きさの仮定（worldLandmarks の実寸）と画角の推定に依る。相手がゴーグルを着けていると頭の点（両目）の推定がずれうる。
  対応づけは方向・位置の近さ・体の向きの簡易なもので、人を見分けてはいない（相手が 2 人以上で申告が古いと入れ替わりうる。化身を出していない人が相手と同じ向きを向いていると付きうる）。
  体の向きの関門（`?facingMaxDeg=60`）と補正の関門（`?corrGateM=1.5`）の既定値は見込みで、**実機未確認**（H7・H8 で `fDeg=` / `corrM=` を記録して決める）。
  補正の関門は、相手のアンカーが跳んで申告が大きく動いたあとに見失い、**前回結んだ位置から 0.5m 以上動いて**（または 3 秒以上たって）戻ると、補正が弱まり切る（`?corrDecaySec=10`）まで本人にも結ばないことがある
  （前回の位置の近くに戻れば直近の頭の位置での再捕捉で結ぶ。自分のアンカーの跳びは補正を捨てるので起きない）。
  **自分のアンカーが無いうち（マーカーを見る前）は、別の人に付くことがある**: 化身を出している相手 1 人・映った人 1 人なら向きを確かめずに結ぶ（only-one-unchecked）ので、映ったのが化身を出していない人でもその人に付く。
  そのまま続けて追いかけている間は、アンカーができた後も付いたまま（続けて追いかけている tracked には関門を掛けないため）で、その差を補正として学ぶ。
- **2026-09-28 の実機で分かったこと（「化身を出した人ではない人の背中に化身が付くことがある」）**: 鏡（iPad）は、2 人が同じくらいの距離に映ると化身が 2 人の間を行き来した（約 6 分で `event=assign` 228 回。`assign p28→1` / `p28→0` が 0.1 秒おきに交互）。
  3D の位置での対応づけ（旧 `?mirrorMatchM=0.5`）が Pose の距離のぶれ（数十 cm）で外れ、そのたびに近い順で選び直していたため → 画像の上の位置で追いかけ、見えている間は付け替えないようにした。
  ゴーグル（iPhone）は、申告の方向とカメラの方向のずれが 29°〜167° で declared-dir がほとんど効かず（2 回）、対応づけは only-one と tracked だった。化身を出していない人が 1 人だけ映ると only-one でその人に付き、補正として学んでいた → 体の向きと補正の関門を足した。**どちらも PC 確認済み・実機未確認**（M7・M8・H7・H8）。フェイクのマーカーでも、この配置でアンカーの向きが約 14° ずれていた（単一マーカーの向きの推定の誤差。段階 3 の方向はカメラの値なのでこの誤差を受けない）。
- 段階 3 の A の実機の原因（getAsFloat32Array の読み戻し）は未確定。skel は骨格からの近似なので、服・髪・持ち物の輪郭は隠れない。
- 鏡モードの前面カメラの画角はカメラ名からの推定（`getSettings` から取れない）。外れると距離（化身の大きさと足元の高さ）がずれるので、実機で `?camFov=` を合わせて記録する。
  カメラは水平に置く前提（ジャイロを使わない）で、傾けると床・化身も傾く。誰の化身かは「最初は近い順 × 参加順、以後は画像の上の位置で追いかける」簡易な対応で、人を見分けてはいない。
  画像の上のしきい値（`?mirrorMatchImg=0.15`、0.05 から 0.5/秒で広げる）は見込みで、**実機未確認**（M7・M8 で `dImg=` / `dImg2=` を記録して決める）。
- 段階 2 の最初の実機（2026-09-27）で分かったこと: iPad で前面の超広角カメラが選ばれていた（共有の `passthrough-camera.ts` を背面だけ選ぶように直した）、40 秒見失った相手の化身が半分の薄さで出続けた（`?staleHideMs=` で消すようにした）、
  iPad で一度も人の形が出なかった（前面カメラに本人の顔が大きく写っていた。原因は未確定なので診断と `?maskDebug=1` を足した）、iPad は Pose を回すと fps 14〜20（検出の回数を自動で下げるようにした）。
- 段階 1 の実機で、マーカーを見直したときに自己位置が最大 1.6m 跳んだ（`event=marker-found ... Δ=1.59m`）。段階 2 では相手の化身もその分だけ動いて見えるが、`?remoteSmoothSec=` でなめらかに寄せる（跳びそのものは減らない）。
- 人の形で隠す前後の判定は「持ち主の頭までの距離 − 0.15m」だけで決めている。相手の体の奥行き（腕を前に出す等）や、別の人（持ち主ではない人）がどの距離にいるかは見ていない（別の人の形の上でも、持ち主の頭より奥の部分は隠れる）。
- PC の確認（`?fakeperson=1`）は MediaPipe の代わりに合成の形のマスクを使う（化身を描かないフレームの背景の画素がフェイクの人の色かどうかで人の中・外を分けて数え、シェーダーと同じ式を使わずにマスクの座標が背景と一致することも確かめている）。
  本物の PoseLandmarker は、初期化とマスクの更新（人が写っていない映像で）までをヘッドレスで確かめている。人の写った実写の静止画はライセンスが不明なので使っていない。**本物の Pose で人の輪郭どおりに隠れるかは実機で確認する**（S2）。
- 主観の前傾 35° では、見上げると化身の顔を下（あご側）から見る形になる（化身の顔は前下を向くため）。見え方は実機で `?selfLean=` / `?selfFaceAhead=` / `?selfBack=` を振って決める。
- 主観の化身は 3DoF（ジャイロ）なので、歩いても化身は頭についてくる（位置はマーカーのアンカーに依らない）。
- スキンメッシュの境界球は使わず、カリングを切っている（README どおり）。見えていないときは描かない（見上げフェード 0・不透明度 0 で非表示）。
- ペガサスのオーラの帯（`PA_FX_Aura`）は主観では出さない（自分の頭を囲んで視界を横切るため）。俯瞰画面では翼を開き切ったあとに出す。

## Cloudflare へのデプロイ

化身だけを Cloudflare Workers（静的アセット + Durable Object）に出す。ビルドは `vite.keshin.config.ts`（全体の `vite.config.ts` とは別）、配信は `deploy/cloudflare/`（`wrangler.jsonc` / `worker.ts` / `keshin-room.ts`）。

前提:

- `npm run fetch:keshin` でモデル 4 体を `local-assets/keshin/` に置いておく（無いとビルドが止まる）。`public/models/pose_landmarker_lite.task` も要る（無ければ `npm run fetch:models`）
- `npx wrangler login` で Cloudflare のアカウントにログインしておく

手順:

```sh
npm run fetch:keshin                                          # モデル 4 体を local-assets/keshin/ にコピー
npm run build:keshin                                          # dist-keshin/ に出す
npx wrangler deploy --config deploy/cloudflare/wrangler.jsonc  # dist-keshin/ と Worker を出す
```

公開 URL（Worker 名 `mobile-mr-keshin`。2026-10-02 に初回デプロイ）:

| 端末 | 用途 | URL |
|---|---|---|
| iPhone（ゴーグル） | 化身を出す人のページ | <https://mobile-mr-keshin.na2kera.workers.dev/demos/ex9-1-keshin/> |
| iPad | 鏡モード（前面カメラに写った人の背後に化身） | <https://mobile-mr-keshin.na2kera.workers.dev/demos/ex9-1-keshin/mirror> |
| PC | 俯瞰画面（全員の頭と化身を上から見る） | <https://mobile-mr-keshin.na2kera.workers.dev/demos/ex9-1-keshin/overview> |
| PC | マーカーの印刷 | <https://mobile-mr-keshin.na2kera.workers.dev/demos/08-splatoon/markers> |

- 全員が同じ room に入る。何も付けなければ room は `demo`。分けたいときは全部の URL に同じ `?room=<名前>` を付ける（英数字・`_`・`-`、32 文字まで）
- `https://mobile-mr-keshin.na2kera.workers.dev/` だけでも iPhone 用のページへ飛ぶ。`overview.html` / `mirror.html` と書いても拡張子なしの URL へ転送される

- `dist-keshin/` に入るのは化身の 3 ページ（index / overview / mirror）・マーカー印刷ページ（`demos/08-splatoon/markers.html`）・JS と MediaPipe の wasm（`assets/`）・`models/pose_landmarker_lite.task`・`favicon.svg`・`local-assets/keshin/*.glb`。
  `public/vendor/`（OpenCV・AlvaAR・AprilTag）と `hand_landmarker.task` は化身で使わないので入れない（合計 28MB 前後、1 ファイルの最大は wasm の約 12MB。Cloudflare の上限は 1 ファイル 25MB）
- 別のアカウントにデプロイすると、URL のホストは `mobile-mr-keshin.<workers.dev のサブドメイン>.workers.dev` になる（上の表の `na2kera` の部分が変わる）
- **モデル（GLB）は公開 URL から誰でも取れるようになる**（`/local-assets/keshin/<file>.glb`。dev サーバーだけで配っていたときと違う）
- 実機のログは `npx wrangler tail --config deploy/cloudflare/wrangler.jsonc` で見る
- 既知の制約: Room の状態は Durable Object のメモリだけに持つ（再起動・退避で消える）。WebSocket のハイバネーションは使っていない（つないでいる間は Durable Object が起きたまま）。
  heartbeat（ping/pong）が無いので、スマホのスリープや Wi-Fi 切断で半開きになった接続は検出まで数分かかりうる（その間その人は Player として残り、8 人の枠を 1 つ使う。同じタブで戻れば session 鍵で置き換わる）。
  Room 数の上限（dev サーバーの 64）は無い（Room 名ごとに Durable Object ができる。公開 URL なので必要になれば Cloudflare の WAF のレート制限で抑える）。
  実機ログ（`/api/client-log`）には **訪問者全員の console ログ**が来る（`?remoteLog=0` 以外で常に有効）。同じホストからの送信だけ受け、1 リクエスト 256KB・200 件までに抑えている。
  マーカー印刷ページの「俯瞰画面へ」「プレイヤー画面へ」（08 のページ）は入れていないのでリンク切れになる
